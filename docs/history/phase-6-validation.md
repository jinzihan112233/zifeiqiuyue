# P6 评论、回复、举报与管理：实现、教程与验证

2026-10-21。本机功能与自动验证已完成，浏览器合成操作已验证；真机、200% 缩放与完整键盘专项仍待使用者验收。本记录不代表公网部署或全面安全审计通过。实施步骤见 [P6 计划](phase-6-plan.md)。

## 实际交付

- `/articles/<slug>`、`/posts/<slug>` 和兼容阅读入口新增“读后回响”，动态分页读取；支持整篇评论、回复再回复、编辑和删除。
- 文字批注关联统一评论，原发布快照、引用及偏移保留；侧栏可进入评论与回复，正文只保存于评论集合。
- `/account` 新增“我的评论与回复”，批注入口指向对应历史版本。父内容下架后不返回评论正文或批注引用。
- `/workspace/discussions` 提供管理员举报队列、上下文、处理理由、隐藏/恢复、下架/恢复、锁定/解锁、封禁与驳回。阅读页也可管理隐藏与锁定。
- 通用评论和举报集合不开放读取或写入，前台使用显式投影；GraphQL 继续关闭，私有响应使用 no-store。

## 使用教程

1. 登录后打开公开文章或帖子，在正文下“读后回响”输入评论并发布。首次发布即公开；失败保留文字，网络重试使用原请求标识。
2. “展开讨论”分页查看该根评论的全部回复；选择“回复 #编号”回应具体评论。继续回复保持同一根关系，界面只有两级缩进。
3. 作者可编辑自己的评论；保存后显示“已编辑”。旧修订保存失败时保留输入。隐藏项编辑后仍隐藏。
4. 作者删除须确认，正文不可恢复；保留占位及他人回复，禁止直接回复被删占位。关联批注引用也擦除。管理恢复不恢复已删除正文。
5. 在内容或正常评论旁点击举报，填写理由。同一用户对同一未结目标不重复创建举报。
6. 管理员从工作台进入“举报与讨论管理”，查看管理上下文，选择动作并填写理由。处理与审计同事务提交，过期决定返回冲突。举报人与内部处理文字仅管理员可见。
7. 管理员也可在阅读页填写管理理由后隐藏/恢复评论、锁定/解锁讨论。锁定保留阅读和作者修正，禁止新增评论、回复与批注；不影响举报。

评论最多 5,000 个 UTF-16 单位，与浏览器 maxlength 和已有服务端限制一致；基础 Markdown 支持强调、引用、链接、列表、代码，不支持图片与原生 HTML。发言额度由评论、回复和批注共享：账号每分钟 5 条、北京时间自然日 200 条，本机 IP 桶每分钟 60 条、自然日 2,000 条。举报另限每账号每分钟 5 条、滚动 24 小时 30 条，本机 IP 每分钟 60 条。本机所有请求共享 IP 桶，不能视为公网代理识别实现。

## 迁移、清除及恢复

迁移为 `20261021_145839_discussion`：新增评论、举报及讨论状态；逐条回填旧批注对应的顶层评论，核验正文、作者和内容后移除重复正文列。数据库触发器拒绝修改评论作者、内容、父根关系，并验证新回复根关系。索引支持根评论与回复分页，未结举报有唯一约束。

先执行 `npm run app:migrate -- --test`，通过后执行 `npm run app:migrate`；重复执行不重复回填。已在测试库及开发库应用。向下迁移主动拒绝删除新讨论数据，不能把恢复旧库作为无损回退。

内容下架同时限制讨论、个人中心与引用；恢复不解除单条隐藏或讨论锁定。敏感清除预检包含评论/举报数量与修订指纹，确认后擦除评论正文、请求摘要、批注摘录、举报理由及管理备注，保留必要关系和终态。最新独立清单重放执行同一清除逻辑。旧备份先隔离恢复并迁移到相应结构，再重放最新清单后开放访问。
