# P2 内容基础与迁移工具：实现与验证

> 历史阶段记录：功能、测试数量和本机资料反映当时环境。当前启动方式见 [开发与维护指南](../development.md)，阶段进展见 [建设路线图](../community-build-roadmap.md)。


日期：2026-10-21。本阶段沿用 P1 的 Next.js、Payload、PostgreSQL 和本地受控媒体目录，未新增依赖、未开放公众注册、未部署到外部服务。

## 1. 交付与步骤对应

| 步骤 | 实现 |
| --- | --- |
| 基线 | `scripts/backup-content-baseline.cjs` 备份本机开发/测试库、媒体及原始内容哈希 |
| 标识与类型 | 内容/快照/媒体稳定标识，保留旧 slug，区分文章/帖子与审核/可见性 |
| 四段 Markdown | `content-format.ts` 校验顶层章节、顺序、空段、简介纯文本；草稿可暂不合规 |
| 媒体与渲染 | 复用 P1 渲染器；受控图片关系、无损 WebP、历史字节保留、原 SVG 来源登记 |
| 发布快照 | 元数据贯穿草稿、提交稿、快照；简介摘要派生；旧快照规范文本与批注不重算 |
| 金句与推荐 | `editorial.ts` 与工作台表单；服务端公开投影过滤隐藏目标 |
| 预览 | 源文件、哈希、格式、引用、重复与冲突检查，生成带摘要指纹的 JSON 报告 |
| 导入 | 稳定来源映射、修订核对、事务锁、整批回滚及本次 UUID 文件清理 |
| 导出 | 文章/帖子/版本/金句 Markdown、媒体、站点配置与清单；默认只导出公开内容 |
| 往返 | 独立恢复库重建后导入、重复导入、再导出，对比规范文本、元数据、媒体哈希及稳定关联 |

新建结构迁移：`20261021_051136_content_foundation`、`20261021_053108_media_origin_index`。前者回填 P1 标识、实际发布日期和媒体关系，不改旧 HTML、正文或规范文本；后者增加私有媒体来源记录与类型/可见性组合索引。

## 3. 验证命令

```powershell
npm run app:migrate
npm run app:migrate -- --test
npm run app:typecheck
npm run app:build
npm run test:community
npm run test:content-community
npm test
npm run check
npm run content:roundtrip
npm run app:restore-check
```

`content:roundtrip` 必须先运行内容测试，读取 `.local/p2-roundtrip-source.txt` 中的测试导出包。它先备份、再重建明确命名的本机 `zifeiqiuyue_restore` 数据库中的 `community` schema，并使用新的独立媒体目录。开发库和测试库不会被此命令清空。该命令是隔离恢复演练，不能用于生产库。

`app:restore-check` 仍用于数据库全量恢复检查；内容包往返不替代它。

## 4. 自动测试覆盖

P2 的 13 项集成测试覆盖：

1. 章节顺序、重复、空章节、代码围栏、摘要与日期校验。
2. 行内/引用式图片映射，保留代码和普通链接。
3. 编辑/成员权限、缺段拒绝提交、普通帖子自由结构。
4. 冻结元数据、摘要、共用预览与重复 slug。
5. 新版本、下架和旧批注定位保持一致。
6. 关联金句/推荐隐藏与独立金句公开。
7. 六篇旧文只读预览、不写媒体与数据库、原文往返。
8. 篡改文件、路径越界、缺少媒体和人工重新封装清单。
9. 幂等导入、源更新、在线修改冲突。
10. 过期预览、slug 冲突保护。
11. 中途失败的数据库回滚及媒体文件清理。
12. 旧文未公开、日期未核验、重复导入。
13. 完整内容包的正文、版本、金句及媒体序列化往返。

## 6. 实施中修复的问题

- Markdown 引用式图片的运行时解析对象没有预期行号；改为受限的源码目标映射，并加入引用式、代码和普通链接回归用例。
- Payload 会再次编码 WebP，初次测试暴露入库哈希与文件字节不一致。新上传使用统一无损 WebP；导入验证图片后，在事务提交前保留归档原字节，记录正确文件大小。仅修正了首次失败测试生成的两条测试媒体哈希，未改开发库用户内容或旧 P1 媒体。
- 同一数据库事务中的集合读取改为顺序执行，避免在同一 pg 连接上并行查询。
- 独立恢复库重建 schema 后显式恢复运行账号的表/序列权限，不依赖已随旧 schema 删除的默认授权。
- HTTP 测试补上真实浏览器携带的 `Sec-Fetch-Site` 标头，避免把 Payload 因标头缺失而拒绝 Cookie 的请求误判为角色权限测试成功；服务端同源校验没有放宽。

## 7. 边界与限制

- 未核验真实视频文案；六篇旧文仍须人工整理四段，不能视为已发布真实文章。
- 静态站和新社区尚未切换，仓库更改不实时覆盖数据库；来源切换属于 P9。
- 数据库和普通异常的回滚已经验证；突然断电/进程被强制终止可能留下不可公开的孤立 UUID 文件。大批量导入与文件垃圾回收属于后续运维工作。
- 导入/导出按本机微型社区规模整体预览，不承诺超大内容包的容量与流式处理能力；工作台列表当前最多 100 项。
- 复杂图片目标语法须人工整理后导入；不支持未知快照渲染版本。
- 历史快照仍可在父内容公开时阅读；敏感信息永久清除、清除记录重放与备份保留策略属于后续阶段，本阶段没有永久清除接口。
- P1 已记录的依赖告警仍适用；本阶段未新增依赖，没有把本机测试表述为公网安全审计。
- 现有工作区包含 P0/P1 未提交变更与原用户文章修改。本阶段保留它们，没有混合自动提交或推送。

内容格式和命令详见 [内容维护指南](../content-guide.md)。本机报告和截图保存在 `.local/`，不提交 Git。
