## 1. 页面与入口

| 地址 | 行为 |
| --- | --- |
| `/` | 数据库驱动的公开首页：纸本封面、最多四篇推荐、三条摘句 |
| `/articles` | 公开站方文章目录，每页 12 篇 |
| `/articles?page=2` | 分页目录，数据库先排序再分页 |
| `/articles/<slug>` | 当前发布快照，服务器输出正文 |
| `/articles/<slug>?version=<stableId>` | 指定历史快照，明确提示历史版本 |
| `/workspace` | 原 P2 内容工作台；编辑、审核与媒体上传继续保留 |
| `/admin` | 原 Payload 后台 |
| `/lab/read/<数字ID>` | 原验证阅读入口，返回链接改到 `/workspace` |
| `/index.html` | 308 跳转到 `/` |
| `/articles.html` | 308 跳转到 `/articles` |
| `/read.html?id=<旧ID>` | 308 跳转到对应 slug；参数缺失、重复或非法则 404 |

旧地址跳转针对新应用 HTTP 服务。根目录离线 HTML、静态 CSS/JS、文章文件和原 SVG 均保留，仍按原方式双击浏览及构建。

## 2. 数据与权限

新增 `src/modules/public-reading.ts`，集中处理首页、目录和阅读的公开数据投影。复用现有 Payload PostgreSQL 连接，不另建连接池、不新增依赖、不增加数据库结构。

- 目录仅筛选 `kind=article AND visibility=public`，并确认当前快照属于该内容。
- 查询只选择展示所需列，不查询工作稿、提交稿、用户私密字段或内部来源记录。
- 当前版和历史版均检查父内容公开状态；版本必须属于当前文章，不能用别篇版本拼接。
- 金句链接固定到所引用的发布快照；隐藏目标后，金句与推荐同步退出公开查询。
- 社区帖子不进入文章目录；现有帖子验证阅读保留。
- 页面按请求读取，关闭跨请求页面缓存；使用普通链接访问，避免预取缓存继续展示已下架内容。
- 游客可阅读公开正文与批注；写批注仍通过现有认证及同源写入接口。正文 DOM 不混入按钮或版本导航。

SQL 固定使用现有 `community` schema，通过参数化语句传入 slug、版本和页码。查询日期排序发生在数据库中，避免取一页后再排序导致重复、遗漏。

## 3. 日期规则

1. 有已核验 `originalVideoDate`：显示和排序使用该日期，标为“原视频”。
2. 没有原视频日期：使用快照 `publishedAt` 对应的北京时间日期，标为“本站发布”。
3. 不使用 `legacyDate` 作为真实视频日期。
4. 日期相同，以稳定内容标识升序排列。
5. 版本列表显示北京时间；底层时间保持原 ISO 值。

排序采用 SQL 表达式，不引入第二份人工维护日期。以当前微型社区规模为目标；本阶段没有生产容量压测或跨表日期排序性能承诺。

## 4. 界面实现

- `public.css` 以旧静态站纸本样式为基础，保留浅黄、宋体标题、暗朱红、细线和线描。
- 工作台样式移到 `.workspace` 范围内，避免其表单和布局规则污染公开页面；旧应用的未使用 `site.css` 已移除。
- 首页简介读取首页配置，推荐不足四篇、金句不足三条时按实际数量展示。
- 没有公开文章时显示整理中的空状态，不用草稿填充，不自动补写或发布六篇旧文。
- 阅读正文直接使用发布快照 HTML；复用原 Reader 的选字、定位和提交逻辑。
- 文章标题及描述读取冻结版本，规范地址指向当前文章；历史 URL 标为不索引。分页目录各有对应规范地址。
- 不可用文章/版本/页码使用 404 页面。数据库错误继续抛出到错误边界，提供重试，不伪装成空目录。
- 窄屏改为单列，宽表格和代码在自身区域滚动，保留浏览器缩放、选字与焦点样式。
