# 用户 Tag 与权限

四级 Tag 是正式权限而不是仅改变昵称颜色。注册与修改 Tag 均由服务端验证。

| Tag | 昵称色彩 | 能力 | 能分配的 Tag |
| --- | --- | --- | --- |
| 普通（regular） | 黑色 | 评论、回复、社区帖子；不能发表站方文章或审核 | 无 |
| 小秋月（moon） | 蓝色 | 与普通用户相同 | 无 |
| 管理员（admin） | 紫色 | 站方文章和社区内容、审核、讨论管理、用户 Tag 管理 | 普通、小秋月 |
| 站长（owner） | 金色 | 最高管理权限，可任命或撤销管理员 | 普通、小秋月、管理员 |

访问 `/account/tags` 在个人中心设置用户 Tag。邀请码可以选择普通、小秋月；只有站长可以生成管理员邀请码。站长身份不可通过网页或邀请码授予；管理员不能修改管理员和站长的 Tag。改变权限会让目标用户退出全部当前会话。

## 数据兼容与升级

原 `role` 字段继续供后端权限判断：普通/小秋月 = member，管理员/站长 = admin。首次迁移时原管理员变为站长、原编辑变为管理员、原普通账号变为普通，因此需要先确认历史账号名单。

原有邀请码默认归入普通 Tag。历史邀请码不会因邀请者改 Tag 自动失效，请核查并撤销不需要的高权限邀请码。

### 生产部署步骤

生产迁移前备份数据库、媒体、清除清单并验证恢复。停止原生产 Next.js 实例，保持 PostgreSQL 运行，然后依次执行：

```powershell
npm run prod:backup
npm run prod:restore-check
npm run prod:migrate
npm run prod:build
npm run prod:start
```

只对生产迁移一次，不要直接拿开发迁移配置连生产库。生产数据库升级前应确认现有站长账号和现有邀请码。开发/测试库分别用 `npm run app:migrate`、`npm run app:migrate -- --test`。
