# 批注与版本阅读规则

文章与帖子共用批注功能。整篇评论属于内容；文字批注属于某个不可变发布快照，其回复沿 P6 的父评论与根评论关系继续讨论。P0 曾限定帖子首版不提供选字批注；当前应用已开放两类内容，P7 沿用现有行为，历史文档保留当时约定。

## 定位依据

现有定位版本保持 `p1-markdown-dom-v1`。服务端使用同一次 Markdown 渲染结果的正文元素 `textContent` 生成规范文本；浏览器逐个文字节点映射，不能使用 `innerText`、自行拼接段落换行、折叠空白或 Unicode 归一化。

正文内部标题、段落、列表、表格、链接文字和代码参与定位。页面标题、导航、按钮和表单不属于正文；图片不提供定位文字，图片替代文字仍保留可访问性职责。选区不允许跨越图片或其他排除元素。换行完全以快照保存的文字节点为准，不因视觉换行重新计算。

范围为 Unicode 码点的 `[start,end)`：`🌙` 一个码点、两个 UTF-16 单位；`e` 加组合音调为两个码点，不与预组合字符 `é` 自动等同。DOM Range 边界使用 UTF-16，转换时拒绝截断代理对。组合 emoji 可能由多个码点组成，不能用可见字形数作为偏移。

引用必须等于规范文本对应切片。前后文各最多 24 个码点，由服务端重新计算。创建请求携带快照 ID、渲染规则版本、范围、引用、上下文、评论正文和请求标识；版本缺失或变化时要求刷新并保留输入，不猜测旧标签页的选区。

未知渲染版本仍可阅读保存的正文和可见引用，但不能创建新定位或猜测高亮。若以后改变规范文本规则，应增加版本实现并保留旧版本处理，不重写旧快照。

## 创建、阅读与回退

1. 登录后在正文选择连续文字，点击出现的“批注所选文字”，确认引用再填写批注。选择本身不会移动焦点或弹出软键盘。
2. 键盘可展开“按原文引用创建批注”，填写完全一致的文字，再从带位置和上下文的匹配结果中明确选择。重复句不默认取第一处。
3. 保存失败保留正文与选区；重复请求只创建一份。选择另一个引用时保留输入，但生成新的提交标识。取消选区也保留未发布文字；离开前可下载本地批注草稿。
4. 侧栏每页 20 条，按创建时间及 ID 稳定排序。直接批注链接独立读取目标，不受当前分页限制。
5. 当前选择的一个批注高亮；重叠批注逐个切换。浏览器支持时使用 CSS Custom Highlight，不拆分或包裹正文节点；否则使用原生选区作为退化强调。
6. 直接链接包含版本、批注 ID 和根评论 ID。个人中心中的批注回复也沿根批注回到原版本；旧批注不会自动迁移到新版文字。
7. 无法定位时保留合法引用及原版本入口。隐藏、删除或父内容下架后，公开接口不再返回原引用；敏感清除及恢复重放沿用 P6，不能通过旧链接恢复摘录。

原生选择、长按、系统菜单与软键盘仍需要真实设备验收。浏览器模拟尺寸和自动测试不能证明手机专项通过。
