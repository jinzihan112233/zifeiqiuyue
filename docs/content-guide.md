# 内容维护指南

离线站和社区应用使用不同的内容来源与图片规则。根据维护入口选择对应章节，仓库文件与数据库不会自动双向同步。

| 维护入口 | 数据来源 | 图片规则 | 操作方式 |
| --- | --- | --- | --- |
| [离线内容维护](#离线内容维护) | `content/`、`assets/` | 本地资源，可保留外链；SVG 仅用于可信仓库资源 | 编辑文件后构建 |
| [社区内容与内容包](#社区内容与内容包) | PostgreSQL、受控媒体 | 上传仅 JPEG/PNG/WebP，正文拒绝远程图片 | 工作台编辑或显式导入导出 |

真实文章和金句分别核实出处与授权，再将各自的 `demo` 改为 `false`。初始化环境见 [开发与维护指南](development.md)。

## 离线内容维护

### 新建文章

例如创建 `content/articles/example.md`。文件名 `example` 是稳定的文章 ID，对应 `read.html?id=example`；改名会改变链接。

```markdown
---
title: "文章标题"
published: "2026-10-21"
type: "人物独白"
description: "用于首页卡片的一两句摘要。"
sourceUrl: ""
demo: true
---

这里是一段正文，可以包含**粗体**、*斜体*和~~删除线~~。

## 一 · 正文小标题

### 更细一级的标题

> 这里是引用段落，仍需核实出处。

![图片内容的文字描述](../../assets/images/example/landscape.webp "可选的图片说明")

- 无序列表
- 第二项

1. 有序列表
2. 第二项

[原始作品](https://www.bilibili.com/)

---
```

模板中的图片地址是示例，使用前请先放入真实图片，否则构建会报错。首页文章主标题来自 `title`，正文建议从 `##` 开始。日期必须加引号，使用 `YYYY-MM-DD`；真实文章填写原视频发布日期，演示文章填写示例日期并保持 `demo: true`。

现有 `libai.md` 展示标题、粗体、斜体和本地图片；`freedom.md` 展示引用段落。Markdown 不负责自由选择字体家族、字号或颜色，这些由 `assets/css/site.css` 统一控制，以保持纸本风格。

### 图片

- 存放位置：`assets/images/<文章ID>/`，文件名建议简短、明确。
- 本地图片路径相对于当前 Markdown 文件，例如 `../../assets/images/libai/road-to-changan.svg`；构建会转换为网页可访问的路径。
- 可使用 PNG、JPEG、WebP、AVIF、GIF 或 SVG 等浏览器支持的格式，不需要额外插件。大照片建议先压缩。
- `![替代文字]` 必须描述图片内容，图片加载失败或使用读屏器时仍能理解。
- 也支持 `https://` 或 `http://` 图片地址，但外链图需要联网，离线浏览建议使用本地图片。
- 引号里的说明是原生悬停提示；需要可见图注时，在图片下另起一段文字。

图片会自适应阅读宽度，保留原始比例并延迟加载，不会挤出手机屏幕。只使用有权使用的图片，不要把示例线描当作视频画面。

### 金句

所有金句集中维护在 `content/quotes.json`，数组顺序就是首页显示顺序。每条保留以下字段：

```json
{
  "id": "quote-example",
  "text": "待展示的句子。",
  "attribution": "出处或署名",
  "articleId": null,
  "sourceUrl": "",
  "demo": true
}
```

- `id` 唯一，不随展示顺序改变；`text`、`attribution` 都不能为空。
- `articleId`：确实出自站内文章时填写文章 ID，否则保留 `null`；构建会检查关联文章存在。
- `sourceUrl`：可填写核验过的网页来源，无来源时保留空字符串。
- 首页署名优先链接到 `articleId` 对应的站内文章；没有关联文章时链接到 `sourceUrl`；两者都为空时仅展示文字。
- `demo` 控制该金句的演示标识；只有核验并明确出处后才改为 `false`。

金句存纯文本，不解析 Markdown，也不从文章里自动随机抽取，避免来源混淆。建议首页保持三条短句。

### 首页推荐

修改 `content/site.json` 的 `featuredIds`，建议保留四个文章 ID：

```json
{
  "featuredIds": ["libai", "freedom", "sushi", "dream"]
}
```

首页按此顺序推荐，全部文章仍按 `published` 日期倒序。新增文章会自动进入目录，不需要修改三个页面的脚本引用。

### 发布前更新

运行 `npm run build`、`npm test`、`npm run check`，再打开网页检查图片和排版。构建失败时先修复提示中的内容问题；之前成功生成的网页内容会保留。

将 `content/`、新增图片和更新后的 `assets/generated/content.js` 一起提交 Git。`node_modules/` 已忽略，不要提交或分发。

## 社区内容与内容包

### 1. 内容身份与状态

- `stableId`：跨数据库导入导出的稳定标识。禁止重新生成已有内容或快照的稳定标识。
- `slug`：链接标识，沿用旧文章文件名，全站唯一；改标题不改 slug。
- `kind`：`article` 为站方文章，`post` 为社区帖子。编辑只能维护自己名下的站方文章；管理员可以管理全部内容。
- `visibility`：`unpublished/public/hidden/purged`；`purged` 为不可恢复、不可再发布的清除终态（P5 增加）。与提交的 `pending/approved/returned/withdrawn` 状态分开。
- 普通编辑与发布流程中，工作稿可以修改，提交稿冻结，发布快照不可原地改写；新发布生成新快照。管理员敏感清除是受控例外，会清除历史正文与关联引用，保留终态标识和审计事实，详见 [内容管理记录](history/phase-5-validation.md)。导入源更新仅更新工作稿，不替换已有公开快照。
- “站方文章”不是“作者官方授权”的声明；站点继续显示非官方标识。

### 2. 文章结构与元数据

站方文章仅要求标题和非空 Markdown 正文，不再强制含有“开头、简介、正文、后记”四个章节。正文可自由使用 Markdown 标题与分段。

简介（metadata.intro，最多 1000 字符）和后记（metadata.afterword，最多 5000 字符）在编辑器中是两个独立的可选文本框。简介展示在阅读页正文之前，同时作为首页推荐与全部文章页的摘要；留空时卡片不显示摘要。简介在阅读页左对齐，并以稍小、稍浅的样式渲染安全 Markdown；首页与文章列表继续显示纯文本摘要。后记展示在正文之后。两者随工作稿、冻结提交、发布快照和内容包保存，不属于正文批注定位范围。

旧的四章节文章不自动改写；已发布旧版本依然保留正文和历史摘要。社区帖子仍可自由编辑 Markdown。模板见 [文章模板](templates/community-article.md) 和 [金句模板](templates/community-quote.md)。
| 字段 | 用途 |
| --- | --- |
| `title` | 标题，最多 200 字符 |
| `metadata.category` | 栏目，最多 100 字符 |
| `metadata.intro` | 简介，可选，最多 1000 字符；用于阅读页及文章列表摘要 |
| `metadata.afterword` | 后记，可选，最多 5000 字符；置于正文之后 |
| `metadata.demo` | 是否为演示内容；文章与金句独立维护 |
| `metadata.sourceUrl` | HTTP(S) 来源链接，没有时为空字符串 |
| `metadata.originalVideoDate` | 已核验的原视频日期，`YYYY-MM-DD`；未核验时为空 |
| `metadata.legacyDate` | 原数据日期，供整理参考，不自动认定为视频日期 |
| 快照 `publishedAt` | 本站发布版本的时间；归档恢复保留该版本原发布时间 |
| `createdAt` | 系统实际创建记录的时间；导入不伪造 |

旧 `description` 仅存在迁移来源记录/内容包的 `legacy.description` 中，不是第二份可编辑摘要。初次迁移不自动将它改写为简介。

页边批注栏会将同一发布版本、引用范围存在包含关系的可见批注放在一组，并列展示各条批注及其独立定位和讨论链接；分组仅针对当前分页。较长的原文引用默认收缩为约 28 个字符、最多两行，短引用全部显示，点击可展开原文；讨论区的引用也采用较小、浅灰的独立样式。桌面端侧栏根据引用的实际正文位置尽量将批注安排在同一行附近，卡片拥挤时依次错开以避免重叠；屏幕较窄时仍按普通列表展示。

### 3. Markdown 与媒体

支持标题、粗体、斜体、删除线、引用、列表、表格、代码、分隔线和图片。HTML 被转义，危险链接由共用 Markdown 渲染器过滤。预览和发布使用相同渲染器。

- 数据库 Markdown 图片：`![图片说明](media:123)`。
- 内容包 Markdown 图片：`![图片说明](../media/稳定媒体ID.webp)`，版本文件相应使用两层相对路径。
- 图片必须有替代文字，只能引用本包媒体或数据库中获准使用的媒体。
- 不接受远程图片、`data:` 图片和任意嵌入，不自动抓取外部资源。
- 上传输入仅 JPEG/PNG/WebP，最大 5 MiB、单边不超过 8192 像素；转为 WebP 后也不得超过 5 MiB。
- 新上传统一无损 WebP；导入已经验证的历史 WebP 保留原始字节和哈希，缩略图由受控处理生成。
- 迁移支持普通行内图片及单行引用式图片；不能安全转换的复杂目标语法会报错，须先人工整理，不猜测改写。
- 旧仓库内的可信 SVG 做一次转换，原文件仍保留在仓库，并记录原路径、原哈希、媒体稳定 ID；不因此允许上传 SVG。

待审媒体及缩略图为私有；公开内容的历史快照引用可公开读取。下架后若没有其他公开内容引用，该图片不再向游客提供。

### 4. 内容包目录

```text
content-export/
├─ manifest.json           格式版本、内容清单、文件哈希、关联映射
├─ articles/<slug>.md      站方文章：工作稿或默认导出的公开版
├─ posts/<slug>.md         社区帖子
├─ versions/<内容ID>/      不可变发布版本，各自一个 Markdown 文件
├─ quotes/<金句ID>.md      一条金句一个文件
├─ media/<媒体ID>.webp     原图；缩略图导入时重新生成
└─ site.json               站点简介、推荐稳定标识与顺序
```

只创建实际有内容的子目录。`manifest.json` 是关联及哈希清单，不是第二份文章正文。文件头中的 `trailingNewline` 保存原正文末尾是否有换行，供无损往返使用。

金句文件头保存 `stableId/attribution/sourceUrl/demo/order/enabled/content/snapshot`，正文是摘句文本。关联内容与版本均使用稳定标识，不能使用另一套数据库的数字 ID。独立金句的两个关联均为 `null`。关联文章不代表摘句自动成为作者原话。

金句可关联历史发布版本；文章下架时，关联金句和推荐通过服务端公开查询隐藏。缺少版本的旧关联金句只作为禁用记录迁入，等待编辑指定版本。

在线首页推荐自动展示按本站发布时间倒序排列的最新 4 篇公开站方文章（`article`），同一时间按稳定标识排序；帖子与未公开内容不会进入推荐。离线站和内容包继续保留原有推荐配置，在线首页不使用手动推荐顺序。关联金句可引用文章或帖子，链接分别为 `/articles/<slug>?version=<快照稳定ID>`、`/posts/<slug>?version=<快照稳定ID>`，始终定位摘句所引用的版本。

### 5. 导入规则

1. `preview` 读取文件、校验结构/媒体/哈希，生成只读预览；不会写数据库和媒体目录。
2. `import` 必须提供预览报告。执行时再次核对来源、数据库修订及冲突。
3. 新标识创建内容；已导入且相同的内容跳过。
4. 源文件改变且数据库未变：更新工作稿，保留当前公开版本。
5. 数据库已有在线修改、slug 冲突或标识冲突：整批拒绝写入，保留在线修改。
6. 数据库写入在同一事务中进行；普通异常回滚时，只清理本次生成的 UUID 媒体及派生文件。
7. 普通导入默认不公开新内容；仅在新建内容且管理员显式指定 `--restore-publication` 时，才恢复包中的发布/隐藏状态。已有内容仍保留在线状态和当前发布指针。

已清除内容不会导出，内容包不接受 `purged` 状态；目标库已有的清除终态不能通过重新导入恢复。

需要保留被在线修改的记录时，先备份并导出两份内容，人工合并后通过正常编辑发布；不提供强制覆盖开关。

### 6. 常用命令

在项目根目录运行；本地配置与账号先按 [开发与维护指南](development.md) 准备。

```powershell
# 旧静态站 -> 社区草稿，先预览后导入
npm run content:transfer -- preview --legacy --report=.local/import-preview.json
npm run content:transfer -- import --legacy --report=.local/import-preview.json

# 默认只导出公开内容；目标必须是不存在的新目录
npm run content:transfer -- export --directory=.local/export-public-001

# 明确包含草稿、隐藏内容；该内容包应按私有资料保存
npm run content:transfer -- export --include-drafts --directory=.local/export-private-001

# 人工修改内容包 Markdown 后，显式重算并校验文件清单
npm run content:transfer -- seal --directory=.local/export-private-001

# 内容包导入；--test 表示使用隔离测试库及其媒体目录
npm run content:transfer -- preview --test --directory=.local/export-private-001 --report=.local/package-preview.json
npm run content:transfer -- import --test --directory=.local/export-private-001 --report=.local/package-preview.json
```

`seal` 不解决在线冲突，也不修改数据库。错误的章节可保存在工作稿中，已发布历史版本必须合法，不能借此改写快照。

CLI 仅允许本机开发库/测试库；默认使用本地管理员，`--user=editor` 可选择已有编辑账号。它是本机维护工具，不是公开认证接口，不应将终端权限提供给不可信用户。

### 7. 来源切换与 Git

当前：旧静态站以 `content/` 为主来源，运行 `npm run build` 更新离线数据；社区工作台以数据库显示已导入内容。仓库修改不会实时覆盖数据库。

P9 正式切换后：数据库为在线唯一主来源，Markdown 用于显式导入、导出和归档；不运行自动双向同步。

目录职责与 Git 提交边界见 [开发与维护指南](development.md#仓库结构与协作)。不要将含私有草稿的导出包直接上传 GitHub。

内容包不包含账号、密码、会话、评论、批注、审核历史和管理记录；需要恢复整站时使用数据库与媒体备份。快照保留规范文本和渲染版本；不支持的渲染版本必须停止导入，不能猜测批注位置。

#### 文章划线与页内评论交互（2026-10）

- 公开的原文批注用浏览器 CSS Highlights API 淡色涂色，不改变已发布正文的 HTML 或文字索引。点击涂色文字打开页内悬浮窗口（手机为底部浮层），从中阅读批注主评论、按需展开楼中楼与直接回复；按 Escape、关闭按钮或点击外部关闭，未提交的输入会二次确认。
- 高亮标记使用只读 `annotation-markers` 接口（每页 200 个定位项），依版本与内容可见性读取，并沿用原有分页的批注列表、直接定位链接与讨论深链。旧定位规则不支持的记录不猜测位置。
- 文章底部评论按主评论分组，楼中楼默认折叠；追评回复其他追评仍显示在同一层，以被回复者的昵称和引用片段标明关系，避免无限缩进。隐藏或删除的原回复不会再展示其引用内容。
- 所有发布、修改、删除、举报、锁定与审核操作继续调用原服务端权限、额度和并发控制，不新建评论表、不迁移数据。
