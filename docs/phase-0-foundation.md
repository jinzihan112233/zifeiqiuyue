# P0：项目基线、迁移清单与社区实施约定

执行日期：2026-10-21。对应总流程的 P0，不代表 P1 或社区功能已经实现。

本文是 P0 的交付记录，也是 P1 的输入。当前行为以代码和检查结果为准；下文标注“未来”的权限、数据和接口规则尚无服务端实现。实施发现约束不可满足时，先更新规则和验收用例，再继续开发。

## 1. 阶段目标与变更边界

P0 完成：静态站基线检查、现有内容和链接清点、字段映射、权限矩阵、状态转换、版本与媒体约定、仓库规范。

P0 不安装框架或数据库，不新增注册/投稿页面，不改变文章写作格式，不迁移文章或金句存储，不发布外部站点。下一阶段为 P1 最小架构验证。

## 4. 内容词典与字段迁移

### 4.1 内容类型

| 名称 | 定义与边界 |
| --- | --- |
| 站方文章 | 由有权限编辑发布的阅读内容，四段格式；不等于已获得作者官方授权 |
| 社区帖子 | 成员撰写并提交审核的自由 Markdown 内容，不强制四段 |
| 金句 | 独立正文、署名、出处与排序；关联文章不自动证明出自作者原话 |
| 整篇评论 | 面向一篇公开文章或帖子的顶层讨论 |
| 文本批注 | 对文章某一发布快照中文字范围的顶层评论；帖子首版不提供选字批注 |
| 回复 | 对已有评论的回应，可继续回复；始终属于同一篇内容 |

### 4.2 字段映射

| 当前字段/来源 | 未来含义 | 迁移规则 |
| --- | --- | --- |
| Markdown 文件名 | 稳定 slug 与旧 ID 映射 | 保留，不按标题重建 |
| `title` | 标题 | 原样保留，发布时进入快照 |
| `published` | 原视频日期或演示日期 | 保留原值与 `demo`；不伪造社区系统创建时间 |
| `type` | 展示分类，如人物独白 | 与文章/帖子这种内容种类分开 |
| `description` | 历史摘要 | 迁移整理时转为简介候选，不自动覆盖已有人工作出的简介 |
| Markdown 正文 | 工作稿及发布快照正文 | 保留原文；四段整理经人工检查后生效 |
| `sourceUrl` | 来源链接 | 空值保持为空，正式来源由编辑核验 |
| `demo` | 演示身份 | 原值保留，不因导入或发布自动改成 false |
| 金句数组顺序 | 金句展示顺序 | 使用显式排序值，保留原有顺序 |
| `articleId` | 可选的内容关联 | 当前 null 保持空；有出处时再关联具体发布快照 |
| `featuredIds` | 首页推荐关联 | 保留顺序，仅允许最终公开内容进入展示 |

未来日期区分 `createdAt`、`updatedAt`、社区实际发布时间及原作品日期。站方文章简介是摘要的唯一人工来源，列表摘要由简介转换为纯文本；标题、小节或链接不能生成重复的另一份人工描述。

所有规则均为服务端约束，隐藏按钮不能替代。游客为未登录访问状态，成员、编辑、管理员是账号角色；管理员具有管理能力，编辑只具有明确授权的站方内容范围。

| 阅读公开内容与可见评论 | 允许 | 允许 | 允许 | 允许 |

| 提交/撤回自己的待审帖子 | 拒绝 | 允许 | 允许 | 允许 |
| 审核成员帖子 | 拒绝 | 拒绝 | 拒绝 | 允许 |
| 创建/编辑站方文章、金句和推荐 | 拒绝 | 拒绝 | 授权范围内 | 允许 |

补充约束：

- 封禁账号不可登录或继续写入，已有会话也失效；公开阅读按游客能力处理。解封需要新的正常登录，不恢复旧会话。
- 成员、编辑、管理员均不能把自己的普通资料请求变成角色、作者、审核状态或管理状态更新。
- 管理员发布自己的内容也记录真实身份与操作类型，不能伪造另一个审核人。
- 普通角色修改不得移除最后一个可用管理员；管理员不能通过个人资料接口提升自己或绕过管理流程。
- 草稿、提交稿、版本、媒体、计数、关系展开与缓存均遵守父内容权限，不只约束列表页。

## 6. 状态转换与并发结果

### 6.1 工作稿、提交稿与发布内容分离

| 对象 | 状态/操作 | 后置结果 |
| --- | --- | --- |
| 工作稿 | 保存并校验修订号 | 新修订号；旧标签页写入返回冲突 |
| 内容 | 新建为 unpublished | 只有所有者及授权管理者可访问；尚无公开版本 |
| 工作稿 | 提交某个修订 | 生成冻结提交稿 pending，不覆盖已有公开快照 |
| 提交稿 | pending → approved | 生成唯一发布快照，更新内容当前指针，记录审核 |
| 提交稿 | pending → returned | 退回意见入记录，作者在工作稿修改后新提交 |
| 提交稿 | pending → withdrawn | 保留历史，作者可编辑工作稿后新提交 |
| 提交稿 | approved/returned/withdrawn 再作决定 | 拒绝改变终态；重复同一请求只返回既有结果 |
| 站方文章 | 编辑授权发布 | 同样生成不可变快照并留发布记录，不冒充成员审核 |
| 内容 | public → hidden | 正文、历史公开版本、评论、引用与媒体访问同步收紧 |
| 内容 | hidden → public | 管理员显式恢复，重新校验公开引用 |
| 内容 | 清除敏感信息 → removed | 独立不可逆流程，处理快照、摘录、图片和缓存；不走普通保存或恢复 |

工作稿不能被直接用于公开读取。每个内容最多一个 pending 提交；提交后可改工作稿，但需先撤回待审副本才能提交新副本，旧提交内容不变。审批与撤回对 pending 条件原子竞争。

首次批准将 unpublished 内容变为 public；对现有 public 内容批准新版只更新快照，不隐藏旧版。hidden 内容即使批准新版也保持 hidden，恢复公开仍需独立管理动作。成员可以丢弃自己的未提交工作稿；有 pending 副本时先撤回，已发布内容由管理员下架，不通过删除工作稿撤销公开版本。removed 为清除后的终态，恢复普通编辑历史不能重新公开被清除内容。

### 6.2 评论和讨论

- 讨论状态为 open/locked，与内容 public/hidden 分开：锁讨论保留可见评论，禁止新增顶层评论与回复。
- 作者评论状态为存在/已删除；管理状态为 visible/hidden。作者编辑不改变管理状态，作者删除后保留占位与已有回复，不允许新回复直接挂到该占位。
- 回复属于同一内容，父关系与作者创建后不可改。界面最多两级缩进，不限制关系中存在继续回复。
- 顶层文本批注关联发布快照；其回复只关联讨论关系，不重复建立选区。
- 下架内容的评论不能通过独立接口公开读取；恢复内容不自动解除某条评论的独立隐藏状态。

### 6.3 已推演的冲突场景

| 场景 | 唯一结果 | 后续证明方法 |
| --- | --- | --- |
| 审核 A 时作者继续改稿为 B | 批准只能发布冻结的 A，B 仍为工作稿 | 比较提交哈希与发布快照 |
| 两位审核人同时批准/退回 | 一个状态转换成功，另一个冲突，无第二份发布快照 | 并发请求与数据库约束 |
| 作者撤回与管理员批准同时发生 | 一个 pending 条件更新成功，另一方不得覆盖 | 并发竞争测试 |
| 作者编辑被隐藏评论 | 新正文仍隐藏 | 公开接口重读 |
| 父评论被删 | 留占位，其他人的回复保留 | 删除后查询回复与父关系 |
| 下架后访问旧版 | 游客不可读，管理查看另行授权 | 对正文、版本、媒体、批注逐路请求 |
| 图片修改或换图 | 新媒体记录，重提并重审，旧文件不原地覆盖 | 比较存储键/哈希与提交引用 |
| 重复导入已在线修改内容 | 报告冲突，不覆盖、不创建重复 slug | 重复导入和冲突样例 |

“已推演”仅指规则没有相互矛盾，不代表并发程序或权限实现已经验证。

## 7. 版本、媒体、恢复与切换约束

### 7.1 发布版本与批注

- 每次发布保存 Markdown、展示元数据、规范文本、渲染规则版本、媒体引用及审核来源。
- 发布快照不能被普通更新、编辑历史恢复或定时清理间接改写；编辑历史与发布快照是不同概念。
- 批注位置使用规范文本的 Unicode 码点偏移，保存原引用和前后文；从浏览器 UTF-16 选区转换，并由服务端校验。
- 默认在原发布版本展示高亮。新版仅提供旧版讨论入口，不自动搬迁定位；定位失败不猜测高亮。
- 长期保留不等于永久公开。内容下架时旧版本也受限；敏感清除允许保留不可用占位，清理引用及派生缓存。

### 7.2 图片授权

- 私有对象存储不提供可绕过授权的公开原图或缩略图地址。
- 保存、提交、发布均检查“有权绑定”，不是只检查媒体记录存在或当前可读。
- 媒体文件不可覆盖；换图生成新 ID 和存储键，进入新的提交与发布快照。
- 正文仅引用受控媒体，未来禁止外链图片、`data:` 图片及任意嵌入；来源超链接不受此限制。
- 用户上传首版限制 JPEG、PNG、WebP；现有受信任 SVG 为仓库资源，成员不能自由引用它或上传 SVG。
- 多篇公开内容共享的授权图片，只在仍存在有效公开引用时继续公开。敏感媒体清除优先遮蔽其全部引用，不能仅下架其中一篇。
- 公开读取经过授权媒体入口；缓存不得让下架前的权限永久生效。

### 7.3 账号恢复与官方身份

- 用户名、密码、邀请码注册；昵称不作为账号恢复依据。恢复码只显示一次，数据库仅存哈希，使用后失效。
- 丢失密码和恢复码不承诺自动找回，不通过“知道昵称”或管理员临时猜测身份来交出账号。
- 恢复密码撤销旧会话，但不能解封。生产账号恢复不在 P0 实现。
- 默认采用“站方发布”身份；本站保持非官方说明。作者本人官方授权需单独核实后赋予标识。

### 7.4 内容来源切换

1. 当前继续修改仓库 Markdown 并构建，金句继续使用 JSON。
2. P2 导入先预览、检查重复及冲突；P3 兼容旧链接，P8 试运行。
3. P9 短暂冻结旧内容写入，最后导入并核对，再切换数据库为唯一在线主来源。
4. 切换后仓库文章与金句 Markdown 仅用于导入/导出、示例与归档；不做数据库和仓库双向自动覆盖。
5. 内容包导出保留 `articles/`、`quotes/`、媒体与关联清单；数据库备份另含用户、评论、审核等，不以文章导出代替整站备份。
6. 旧静态站可归档恢复阅读，但上线后不能拿旧数据库覆盖新增投稿。严重故障优先关闭写入、保留数据库，再执行受控恢复。

## 8. 仓库约定与文件职责

### 8.1 当前保留的结构

```text
index.html / articles.html / read.html   当前可直接打开的页面
content/                               当前唯一内容来源
assets/css/、assets/js/、assets/images/ 当前样式、逻辑和受信任资源
assets/generated/content.js            构建产物，仍需提交
scripts/                               内容构建及未来一次性维护脚本
tests/                                 实际行为测试
docs/                                  内容指南、总流程、阶段规则与记录
```

P0 新增 `.editorconfig`，约定 UTF-8、LF、两空格及文件末尾换行；Markdown 保留有意义的行尾空格。`.gitattributes` 同时约定文本文件使用 LF，避免 Windows 的 Git 自动换行与编辑器约定冲突，二进制内容由 Git 自动识别保留。未执行全仓库格式化或重新规范化，不重写已有正文。

### 8.2 P1 起使用的结构约定

```text
src/app/          页面、路由及 Payload 后台接入
src/collections/ Payload 数据集合配置与权限入口
src/modules/     账号、内容、讨论、管理业务动作
src/components/ 可复用展示组件，不承担发布或授权决定
src/migrations/ 数据库迁移，必须进入 Git
```

只建实际使用的目录，不预先创建空模块、仓库多包结构或插件层。具体框架路由组由 P1 按锁定版本接入要求实现，不改变单一应用边界。

### 8.3 Git 与环境规则

- 忽略依赖、缓存、环境真实值、运行时上传、存储、备份、本机辅助数据、框架构建及测试报告。
- `.env.example` 与分环境 `.env.*.example` 仅能包含变量名和占位值，可提交；P1 出现真实配置需求后再创建模板。
- 数据库迁移脚本可以提交，不以通配 `*.sql` 忽略所有 SQL；备份放入被忽略的 `backups/`。
- 静态站源文件、当前生成内容、图片示例、测试和规划文档继续纳入 Git。
- 如果秘密已经被跟踪，新增忽略规则不能撤回历史泄露，必须单独移除跟踪并轮换；不在 P0 擅自重写 Git 历史。
- 当前没有创建远程仓库、推送或部署；后续按明确的发布操作执行。
