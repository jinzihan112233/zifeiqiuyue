# P5 投稿、审核与内容管理：实现、教程与验证

实施日期：2026-10-21。P5 功能已实现，本机自动检查通过，等待使用者验收。Edge 桌面操作已进行部分实测；多尺寸、200% 缩放及真机检查仍待完成，不据此宣称全面安全审计通过。

## 1. 实际交付

| 入口 | 行为 |
| --- | --- |
| `/workspace` | 新建稿件；分页筛选内容、提交记录和图片；管理员审核队列；原站方设置保留 |
| `/workspace/edit/<内容ID>` | 编辑标题、Markdown 和元数据；手动保存、修订冲突提示、本地稿下载、插图及提交 |
| `/workspace/review/<内容ID>?submission=<提交ID>` | 指定冻结稿、当前发布版对照、元数据/图片变化、冻结渲染预览、审核及撤回 |
| `/community` | 公开社区帖子分页目录，按本站发布时间倒序 |
| `/posts/<slug>` | 帖子阅读和历史版本，复用纸本 Reader 与现有文字批注 |
| `/articles`、`/articles/<slug>` | 原站方文章目录及阅读页保留，与帖子按类型隔离 |
| `/account` | 私有稿件链接直接进入对应编辑/审核页；公开内容进入正式阅读入口 |

管理员在编辑/审核详情页填写理由，进行下架、恢复、清除预检和待处理媒体清理。敏感清除需要重新检查范围并输入“永久清除”，不会因进入页面或运行迁移而自动发生。

没有新增依赖、富文本编辑器、自动保存、多人协作、通知服务或 WebSocket。完整评论、回复、举报仍在 P6。

## 2. 内容与权限规则

- 工作稿保存带修订号；失败或冲突不覆盖浏览器中的文字。未保存时不能提交，离开新建/编辑页会使用浏览器支持的提示。提示不能保证应对浏览器崩溃，重要稿件可主动下载。
- 下载本地稿包含标题、元数据及 Markdown；媒体仍引用已有 ID，不是带全部图片的整站导出包。
- 提交复制标题、正文、元数据、媒体 ID 和媒体清单。清单冻结文件名、实际文件哈希和图片说明；Markdown 内的替代文字同时随正文冻结。
- 一个内容只有一份待审稿、一份提交只有一个发布快照。原修订已结束后需要保存新修订再送审；同一请求标识的网络重试返回原提交/决定，不生成第二份。
- 普通成员只管理自己的帖子。编辑可管理自己的站方文章并自行发布；成员帖子仅管理员可审核。管理员自审或代操作留记录，代改、代提交、代撤回要求理由。
- 图片读取权限与绑定权限分开。管理员不能仅凭身份在新正文中绑定别人图片；管理已有稿件可保留已绑定图片。批准校验作者的冻结绑定，不要求审核人拥有图片。
- 退回必须填写 1–1000 字符理由；不再截断超长理由。退回与撤回不因图片缺失或损坏而被阻止。
- 批准被封禁作者的待审稿会被拒绝。账号和会话在写入事务中重新检查；账号行共享锁与内容事务锁定义并发顺序。
- 已公开内容继续编辑只改工作稿。内容下架后，批准新版本不会自动恢复公开。
- 公开接口只读取 public 发布快照；个人中心、编辑、审核和管理 API 为 no-store。公开阅读继续回源，没有新增共享缓存刷新链路。

内部备注仅管理员可见，作者只看可见反馈。操作记录通过受控服务写入，原始集合不开放通用修改入口。

## 3. 本阶段同时修复的问题

1. 原工作台固定取前 100 条：新界面与管理 API 改为服务端分页，旧 workspace 接口也增加页码和分页信息。
2. 退回理由写死、超长文字被截断：改为实际填写及服务端长度校验。
3. 图片失效阻塞撤回/退回：只有批准才执行发布所需的媒体完整性校验。
4. 管理员可绕过图片归属：新绑定不再有管理员通行例外，已有授权绑定在冻结稿中验证。
5. **Payload 修改密码会保留当前 `_sid`**：框架在 beforeChange 后重新计算会话，会覆盖原先清空会话的意图。受控改密码流程现在明确取消保留当前会话，并在内容事务中复查会话仍有效。新增“请求先获身份、改密码后再尝试写入”的测试。
6. 重复清除可能覆盖独立清单中的媒体 ID：清单合并保留历史媒体目标，已清除内容的重试不能丢失恢复时需要重放的信息。

这些是本阶段定向检查的发现；P3/P4 的初步验收与既往自动测试不代表没有其他漏洞。

## 4. 下架、清除与恢复的实际边界

普通下架可以恢复，遮蔽正文、旧版本、关联金句、推荐和批注。独占媒体不再公开；合法共享媒体若仍被其他公开内容引用，保持可读，不声称文件全站消失。

敏感清除预检返回数量与范围指纹。确认后使用独占生命周期事务锁，避免其他稿件在引用检查过程中新增绑定。存在范围外媒体引用时拒绝完整清除，需管理员先解决引用。

清除覆盖运行库中的工作稿、Payload 草稿历史、提交、发布快照、标题/元数据/来源、关联金句、批注正文及摘录/前后文，以及可能复制原文的审核理由、内部备注和请求标识。内容保留终止状态 `purged` 与必要稳定标识，禁止恢复、再编辑、再提交和重新导入；不将占位稿当作正常发布版导出。

自由填写的清除理由可能复述敏感原文，因此校验后不保留其全文，审计只保留操作者、时间、动作和清除事实。独占媒体先撤销读取权限，再按持久任务清理原图与派生图；文件删除失败显示 pending，可由管理员重试，不影响原文已停止公开的状态。

清除不自动识别无结构化关联的手工摘抄，也不能撤回读者已下载的文件。旧导出包和旧备份要单独管理。

独立清除清单位于 `.local/purge-ledger/<数据库名>/`，每个目标一个不含原文的 JSON；它不随数据库恢复回滚。启动时检查清单与库状态，不匹配则拒绝启动。缺少清单的 restore 库也拒绝启动。

恢复必须隔离执行，使用**最新独立清单**重放，然后检查权限和待清理任务，才能开放服务。备份命令会附带当时清单的副本，但该历史副本不能替代最新清单。`PURGE_REPLAY` 只供隔离脚本使用，不可作为正式启动配置来绕过检查。

## 5. 使用教程

### 成员写作

1. 在 `/login` 登录，进入 `/workspace` →“新建内容”，填写固定标识、标题和正文。
2. 创建成功后进入独立编辑页。上传图片，点击“插入光标处”；正文继续使用标准 Markdown。
3. 点击“保存工作稿”，确认修订号递增、状态变为已保存；预览显示点击时的正文，修改后需重新预览。
4. 有冲突时先下载本地稿，不要立即覆盖；确认备份后再读取服务端最新版本并合并。
5. 点击“提交已保存修订”；之后修改工作稿不会改变待审稿。通过提交历史查看反馈或撤回具体提交。
6. 退回或撤回后，修改并保存为新修订再提交。获批后在 `/community` 或个人中心打开发布版。

站方文章仍要求二级标题按开头、简介、正文、后记顺序排列；原六篇旧文不自动补写或发布。

### 管理员审核

1. 工作台选择“审核队列与提交记录”，筛选 pending、帖子或站方文章。
2. 打开具体提交，比较冻结正文与当前发布版，查看来源、元数据及图片变化，预览冻结正文。
3. 通过发布或填写具体理由退回；内部备注不向作者公开。自行发布会记录自审标记。
4. 下架/恢复在详情页操作，必须填写理由；不会批准尚未处理的工作稿。
5. 敏感清除先预检，人工核查摘抄及备份，解决共享媒体引用，再输入“永久清除”确认。处理结果 pending 时使用“重试待处理媒体清理”。

### 运维与本机启动

```powershell
npm run db:start
npm run content:backup
npm run app:migrate -- --test
npm run app:migrate
npm run content:audit
npm run app:build
npm run app:start
```

迁移为 `20261021_113451_publication_management`，增加冻结媒体信息、重试标识、purged 状态、内容操作记录、媒体清理任务和待审唯一索引。未删除旧内容。向下迁移主动拒绝执行，避免误删清除标记和操作历史；回退须使用完整备份与最新清除清单。

若启动报告未重放的清除指令，先停止本机应用、核对数据库与最新独立清单，然后在隔离条件下运行：

```powershell
npm run content:replay-purges -- --isolated --ledger=.local/purge-ledger/zifeiqiuyue_dev
```

该命令只允许明确的本机 dev/test/restore 库。它会按清单实际执行清除，不应对错误数据库或过期清单盲目运行。恢复演练命令 `npm run app:restore-check` 只覆盖指定 restore 库，不覆盖开发库。
