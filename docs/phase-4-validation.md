# P4 邀请码、账号与个人中心

实施日期：2026-10-21。完成本机功能和自动验证，等待使用者验收。P3 已由使用者初步验收通过，仍保留后续统一漏洞审查及未实际执行的专项检查。

## 1. 本阶段交付

| 入口 | 功能 |
| --- | --- |
| `/login` | 用户名、密码登录；安全地返回原文章版本或工作台 |
| `/register` | 邀请码注册，注册后一次性展示恢复码，不自动登录 |
| `/recover` | 账号、恢复码、新密码；成功后领取新码并重新登录 |
| `/account` | 分页查看自己的草稿、提交与退回意见、内容状态、现有文字批注 |
| `/account/security` | 修改昵称、验证旧密码后改密码、重新生成恢复码、确认保存 |
| `/account/invitations` | 管理员生成、复制、撤销邀请码，查看限额、有效期和使用记录 |
| `/workspace` | 沿用写作和审核工作台；未登录时进入统一登录页 |
| `/admin` | 保留 Payload 管理后台，账号创建关闭，密码修改进入账号安全页 |

邀请码管理使用独立的管理员页面，入口同时出现在个人中心和管理员工作台。没有给原始邀请码集合开放通用 CRUD。页面本身不携带秘密，身份和权限由服务端接口重新检查。

全量文章评论、评论回复、公开社区帖子列表仍按后续阶段实施；本阶段个人中心先展示已有文字批注，不把它标为完整评论系统。

## 3. 数据与事务约定

新增 `src/modules/accounts.ts` 集中处理业务；`src/modules/return-to.ts` 只处理安全返回路径。既有流式请求体读取逻辑移到 `src/modules/http-body.ts`，供内容及认证接口共用；即使没有 Content-Length，超限时也会停止读取。页面在 `src/app/(frontend)/(accounts)/`，受控接口在 `src/app/api/account/[...action]/route.ts`，框架原生认证入口在原来的 Payload API 路由适配。

新增集合：

- `invitations`：`codeHash`、有效期、上限、已用次数、撤销状态、创建者。
- `invitation-uses`：邀请码、用户、创建时间；一个用户仅一条注册使用记录。
- `auth-limits`：哈希桶键、计数、到期时间。使用 PostgreSQL 原子 upsert，多进程共享，过期记录自动清理。
- `users`：新增私有 `recoveryHash`、`recoveryConfirmed`。恢复码哈希在通用读取和登录返回前移除，包括管理员读取。

邀请码和恢复码均为 256 位随机值，数据库只保存哈希。密码仍由 Payload 3.91 生成带版本的 PBKDF2 哈希。更改密码时使用相同参数验证旧密码，不创建额外登录会话，并兼容该框架旧格式；升级认证库时需同时复核验证参数和测试。

注册与账号变更使用同一事务级锁，先检查当前状态再写入；邀请码校验、限额、用户和使用记录处于同一事务。该简单做法适合目前微型社区，账号写入串行执行，不承诺高并发注册吞吐。内容发布仍保留原有独立内容锁。

登录限流在账号事务开始前执行，避免大量等待锁的连接占满池后，持锁请求再等待限流连接。已验证 20 个并发登录请求能在 15 连接池下完成。密码错误次数正常持久化，保留框架连续 5 次错误锁定 5 分钟的行为。

迁移文件：

1. `20261021_103842_invitation_accounts`：新表和账号字段；向前迁移不删除旧数据。
2. `20261021_104900_account_invariants`：登录名、昵称及配额的数据库约束；旧数据不符合时明确失败，不自动修正。

向下迁移会删除 P4 新字段和新表中的账号恢复、邀请记录，不能当作无损业务撤销方式。需要恢复时使用完整备份。

## 4. 校验与访问规则

- 账号：3–24 位 ASCII 字母、数字、下划线，统一小写且唯一；创建后不能修改。昵称：去除首尾空白后 1–30 个 Unicode 字符。
- 新密码：12–128 个 Unicode 字符，不 trim、不截断；前端保留足够 UTF-16 输入空间，最终以后端字符校验为准。
- 注册强制普通成员和正常状态，忽略请求中的角色、封禁、会话等额外字段。通用创建入口、首次注册入口和 Local API 非受信写入不能绕过。
- 修改昵称只接受昵称。原生用户修改仍仅供管理员调整权限与状态，修改密码进入受控账号安全流程；最后一名有效管理员保护继续生效。
- 改密码、恢复、封禁、角色变化均撤销旧会话。每个受保护业务继续读取当前有效用户，解除封禁不会恢复旧 Cookie。
- 登录失败统一提示；恢复不公开区分账号不存在和恢复码错误。身份页面/API 使用 `private, no-store`。
- 状态变更要求精确匹配 `APP_ORIGIN`；HTTPOnly、SameSite=Lax Cookie，HTTPS 环境启用 Secure。跨站和缺失 Origin 的提交拒绝。
- 返回地址只能是本站相对路径，拒绝外部地址、协议相对地址、反斜杠、控制字符及认证/API 回跳；保留文章版本参数。
- 密码、邀请码、恢复码不放入 URL、localStorage 或应用日志；一次性明文仅留在当前页面内存中。复制到系统剪贴板由用户主动触发。
- 无邮箱恢复；原生邮件找回、重设密码和解锁入口关闭，统一使用恢复码。会话续期仍保留，须重新确认会话未撤销及账号有效。

限流基线：登录 30 次/15 分钟（本地共享 IP 桶）和每账号 10 次/15 分钟；注册 10 次/小时；恢复 10 次/小时并每账号 5 次/小时；改密码/生成恢复码每账号 10 次/15 分钟。失败请求也计数，不因业务事务回滚而撤销。

当前只面向本机，所有访问共享本地 IP 桶；不相信任意 `X-Forwarded-For`。上线前必须按真实反向代理拓扑配置可信来源及客户端地址规则，不能直接把该本地配置用于公网。

## 5. 使用教程

```powershell
npm ci
npm run db:start
npm run app:migrate
npm run app:seed
npm run app:build
npm run app:start
```

1. 打开 `http://127.0.0.1:3000/login`，用本机 `.local/p1-accounts.json` 中已有管理员登录；此文件仅用于本地初始化，不提交 Git。
2. 进入“个人中心 → 邀请码管理”，设置次数和未来的失效时间，生成并复制邀请码。离开页面后无法再查看码明文。
3. 受邀者在 `/register` 填账号、昵称、密码与邀请码；成功后立即保存恢复码，勾选保存再进入登录。
4. 登录后到账号安全页确认保存，或验证当前密码重新生成恢复码。旧初始化账号没有恢复码，需要先生成。尚未确认保存的账号在退出前会看到提醒，可选择取消退出。
5. 在 `/workspace` 创建、保存并提交稿件；在 `/account` 切换查看草稿、审核意见、公开状态与文字批注。
6. 忘记密码时到 `/recover`，输入账号、恢复码和新密码。保存新的恢复码后重新登录；旧密码、旧恢复码和旧会话都失效。

邀请码已过期、被撤销或额度耗尽时，需管理员重新发码；同时失去密码和恢复码时，不提供仅凭昵称恢复的入口。
