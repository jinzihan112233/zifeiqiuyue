# P1：最小社区架构实现与验证

执行日期：2026-10-21。用途：本机架构验证，尚未上线生产社区。

前置规则见 [P0 阶段交付](phase-0-foundation.md)，阶段关系见 [总流程](community-build-roadmap.md)。现有六篇静态文章、金句、HTML、样式与前端脚本继续保留，本阶段只使用合成内容验证社区基础。

## 1. 本阶段实际交付

- 单一 TypeScript / Next.js / Payload 应用，前台、后台、API 同源运行。
- 本地 PostgreSQL 17.11，开发、测试、恢复三个独立数据库；应用账号没有超级用户、建库或建角色权限。
- 无邮箱用户名密码登录、会话退出/过期/撤销、角色与归属权限、封禁检查。
- 工作稿修订、冻结提交、管理员审核、发布快照、下架与恢复。
- 私有图片上传、文件和缩略图读取权限、图片引用授权、禁止覆盖送审图片。
- 选字批注、服务端范围校验、原发布版本定位、重复文字及 Unicode 处理。
- 可操作的本地工作台、Payload 管理后台、阅读与批注界面。
- 可重复迁移、幂等账号初始化、真实数据库集成测试及独立恢复演练。

本阶段不开放公众注册，不实现邀请码、恢复码、完整评论回复、举报、正式文章迁移或生产对象存储。测试用户由本地脚本创建；所有已完成的安全检查只适用于实际覆盖的路径，不等于渗透测试或生产审核。

## 3. 本机启动方式

### 3.1 已准备好的当前环境

在项目目录执行：

```sh
npm run db:start
npm run app:start
```

访问 `http://127.0.0.1:3000/` 为验证工作台，`http://127.0.0.1:3000/admin` 为后台。后台用于查看数据与管理测试账号，内容写入、提交和审核由工作台的受控业务入口执行，不能绕过审核直接在通用集合接口中修改。

本地账号及随机密码保存在 `.local/p1-accounts.json`，未提交 Git。包括 admin、editor、membera、memberb、blocked；最后一个为封禁样例。不要把 `.local/`、`.env.local` 或 `backups/` 打包分享。

当前开发库有一篇由真实浏览器创建、审核并批注的合成文章，可从工作台进入阅读。它不属于原有六篇静态文章，也不是作者原文。

### 3.2 从干净检出准备环境

1. 安装兼容 Node.js；本次验证环境为 24.20.0。
2. 执行 `npm ci`。
3. 从 [PostgreSQL 官方 Windows 下载入口](https://www.postgresql.org/download/windows/) 进入 EDB 二进制包下载，获取 17.11 Windows x64 压缩包。
4. 解压至 `.local/postgres/`，确认程序路径为 `.local/postgres/pgsql/bin/pg_ctl.exe`；不是再套一层同名目录。
5. 执行 `npm run db:start`：初始化仅监听 127.0.0.1:55432 的独立集群，创建数据库角色、数据库和 `.env.local`。
6. 执行以下命令：

```sh
npm run app:migrate
npm run app:migrate -- --test
npm run app:seed
npm run app:importmap
npm run app:typecheck
npm run app:build
npm run app:start
```

不要先把 `.env.example` 的占位值直接当作真实值使用。自动准备脚本不会覆盖已存在的 `.env.local`，也不会重置已有角色密码。若使用自行配置的数据库，应自行填写模板变量并核验其权限。

初始化脚本重复运行会保留既有账号与密码。如果账号已经存在而本地凭据文件丢失，脚本明确报错，不生成一份与实际账号不匹配的密码清单，也不擅自重置管理员。

### 3.3 开发、检查和停止

| 命令 | 作用 |
| --- | --- |
| `npm run app:dev` | 启动本地开发服务器，首次路由编译可能较慢 |
| `npm run app:build` | 构建生产应用 |
| `npm run app:start` | 启动已构建应用，监听本机 3000 |
| `npm run app:typecheck` | TypeScript 检查 |
| `npm run app:importmap` | 生成/更新后台组件映射，生成文件需纳入 Git |
| `npm run app:migrate -- --create` | 结构变更时创建迁移；不是每次启动都执行 |
| `npm run app:migrate` | 对专用开发库执行待应用迁移 |
| `npm run app:migrate -- --test` | 对专用测试库执行待应用迁移 |
| `npm run app:seed` | 准备本地验证账号，不重置密码 |
| `npm run test:community` | 在专用测试库运行真实集成测试，临时服务器使用 3100 |
| `npm run app:restore-check` | 将测试数据恢复到专用恢复库并检查 |
| `npm run db:stop` | 停止该项目的本地数据库集群 |
| `npm run build` / `npm test` / `npm run check` | 仍然只处理原有静态站 |

开发与生产服务器不能同时占用 3000。停止正在运行的应用后再切换模式。Windows 的数据库脚本使用 ASCII 源文本，避免旧版 Windows PowerShell 误读无 BOM 的 UTF-8 中文字符串。

## 4. 工程与数据实现

### 4.1 源码职责

```text
src/app/(frontend)/       验证工作台、阅读页、纸本样式
src/app/(payload)/        Payload 后台和受权限控制的原生 REST 接口
src/app/api/community/    本站业务动作及读取接口
src/collections/         集合配置、基础访问控制、写入保护
src/modules/             身份校验、事务业务、Markdown 与规范文本
src/migrations/          已提交的初始迁移、结构快照与迁移索引
scripts/                 本地数据库、迁移、初始化、恢复工具
tests/community.test.ts  真实数据库与生产 HTTP 集成测试
```

后台组件映射由 Payload 生成，不能以空对象长期替代；管理首页需要内置的 CollectionCards 组件。Next.js 开发模式生成的根目录 `AGENTS.md` 保留为框架维护指引，它不代表网站功能或用户配置。

### 4.2 数据库与磁盘隔离

| 项目 | 位置/角色 |
| --- | --- |
| 开发库 | `zifeiqiuyue_dev` |
| 测试库 | `zifeiqiuyue_test`，测试脚本检查名字与本机地址 |
| 恢复库 | `zifeiqiuyue_restore`，只供演练，恢复时会清理该库中备份涉及的对象 |
| 应用角色 | `zfq_app`，无 DDL/建库/建角色能力 |
| 迁移角色 | `zfq_migrate`，专用数据库和 community schema 的结构维护者 |
| 本地集群管理角色 | 仅本地准备脚本使用，应用连接串不使用它 |
| 开发图片 | `storage/media/` |
| 测试图片 | `storage/test-media/` |
| 恢复图片 | `storage/restore-<时间>/` |
| 备份 | `backups/p1-<时间>.dump` |
| 运行配置与凭据 | `.env.local`、`.local/`，全部忽略 |

自动结构推送关闭；首次迁移已分别在空开发库和空测试库执行，重复迁移不会创建第二份结构。开发、测试与恢复库目前位于同一本机集群并共用应用角色，不等于生产级环境隔离；P8 应使用独立环境与凭据。

### 4.3 权限与受控写入

- 公共读取只返回公开内容；工作稿和提交稿按所有者/管理员权限读取。
- 用户记录仅本人或管理员可读；成员不能进入后台，编辑不能审核成员帖子。
- 通用集合创建、修改、删除不允许直接绕过业务流程；工作稿、提交稿、发布快照、媒体和批注均受内部写入令牌保护。
- 原生用户创建和首次账号初始化也不能成为公众注册入口；首个管理员由本地脚本准备。
- 角色、作者、公开状态和审核状态不从普通业务请求中自由写入。
- 每次操作检查最新账号状态，封禁或改密码撤销会话；过期或无效令牌不能访问私密内容。
- Cookie 使用 HttpOnly 与 SameSite=Lax，生产 HTTPS 时设置 Secure；本站写入接口额外检查 Origin，设置请求体限制。
- API 和媒体读取使用 private/no-store，身份响应不进入共享缓存；GraphQL 未启用。
- 用户角色变更在事务内串行检查，两个管理员同时降权时也不能移除最后一个活跃管理员。

### 4.4 审核、事务与并发

工作稿保存检查修订号；提交复制标题、正文、图片引用和修订号为冻结副本。审核仅针对该提交 ID。一个内容同一时间最多有一个待审副本，一个提交最多生成一个发布快照。

按内容 ID 使用 PostgreSQL 事务级 advisory lock，让保存、提交、审核、撤回、可见性变更、批注写入对同一内容有明确的先后顺序。状态变更、快照创建和当前指针更新在同一事务完成；失败回滚。通过新版不会隐式恢复已下架内容。

锁所用的事务连接与 Payload 写入共享 `req.transactionID`；事务中的账号查询也复用同一连接，避免并发排队占满连接池后又等待额外连接。已验证 20 个并发提交在配置的连接池容量下正常结束，只有一个成功，其余返回冲突。

这个事务桥接读取 Payload 3.91 适配器的 session 连接，属于明确的版本耦合点。升级数据库适配器时必须重新运行并发、回滚及权限测试，不能假定内部接口永久稳定。

### 4.5 媒体与 Markdown

- 上传只接受实际可解码的 JPEG、PNG、WebP，最大 5 MiB、单边不超过 8192 像素，统一重编码为 WebP。
- 生成随机、不可覆盖的文件名和内容哈希；文件与缩略图均不放进 Next public 目录。
- 正文图片使用 `![说明](media:ID)`；替代文字必填，远程图片、SVG、data 图片不作为用户媒体接受。
- 保存、提交、发布检查媒体绑定权限，成员不能借发布流程公开他人的私有图片。
- 发布后由内容引用决定游客读取；下架会限制原图与缩略图，仍被其他公开内容合法引用的图片保持公开。
- Markdown 禁用原生 HTML；规范文本由 HTML DOM 提取，保留实际文字与换行，避免用正则删标签导致选区错位。

### 4.6 批注

位置固定为发布快照规范文本的 Unicode 码点偏移。浏览器从原生选区计算偏移，服务端重算原引用并验证范围，保存前后文。拒绝伪造、越界和纯空白选区。

高亮逐个处理正文文本节点，不通过插入不可信 HTML 实现。页面文字与快照不一致时保留引用并提示，不猜测定位。批注绑定原快照；发布新版不会将旧批注自动挪到相似文字上。

### 5.2 主要自动用例

1. 无邮箱登录，初始化重复运行不改密码；公众不能直接创建用户。
2. 成员不能读取他人草稿、历史版本或提升角色。
3. 即使请求跳过基础访问控制，集合写入保护仍阻止直接篡改发布快照。
4. 最后一个管理员不能被封禁或降权；两位管理员同时降权仍保留一个。
5. 旧修订号保存返回冲突，审核副本不受新工作稿修改影响。
6. 编辑不能审核成员帖子，重复提交/审核、撤回竞争只有一个结果。
7. 20 并发请求大于连接池容量时不会发生嵌套取连接饥饿。
8. 快照创建后故意抛错，审核状态、快照与当前指针全部回滚。
9. 私有图片、缩略图、借用他人图片、直接换图、下架与共享引用。
10. HTML、危险链接、外链图片、SVG 与损坏图片的处理。
11. 重复中文、跨段、粗体/链接、emoji、组合字符和纯空白选区。
12. 新版本发布后批注仍在原版；下架后旧快照与批注也不可公开读取。
13. 真实 HTTP 登录 Cookie、过期/无效令牌、退出、封禁撤销与解封不恢复旧会话。
14. 直接 REST、首次用户入口、管理页、跨站写入与 no-store 响应。

Payload 管理页可能通过 Next.js 流式响应返回 HTTP 200，再携带受控登录跳转；测试检查实际跳转目标，不将“200”直接等同于已进入后台。

- 已验证开发模式页面和 Payload 后台集合卡片可正常加载。
- 截图保存在 `.local/p1-reader-desktop.png` 与 `.local/p1-reader-mobile.png`，为本机证据，不纳入内容库。
- 这是桌面 Edge 的视口模拟，不是真实手机硬件测试；移动端长按与复杂选区专项仍在 P7。

### 5.4 恢复检查的边界

恢复脚本明确限制来源为本机 `zifeiqiuyue_test`，目标为 `zifeiqiuyue_restore`，并保证两者不同；`pg_restore --clean` 只针对该专用恢复库。媒体复制到新的时间戳目录，不覆盖开发或测试图片。

恢复报告在 `.local/p1-restore-report.json` 中记录当次实际数量和备份位置。逐行比较在恢复后登录和新增验证工作稿之前执行，所以报告中的数量代表源备份，不包含之后的恢复写入探针。

## 6. 已知限制与后续入口

- 当前只监听本机，未配置公网 HTTPS、生产部署、云对象存储或生产监控。
- 媒体公开引用查询有 10,000 条样本上限，工作台列表最多显示 100 条；正式内容迁移前改为关系索引查询和分页。
- 适配器持有初始化连接，命令行任务在所有数据库工作 await 完成后显式退出；测试使用 Node 的 `--test-force-exit`。这不是允许忽略未完成写入，适配器升级后应复查生命周期处理。
- 没有邀请码、恢复码、完整评论回复、举报、金句后台或完整站方文章权限范围；这些仍按后续阶段实施。
- P1 内容都是测试帖子，正式文章类型、四段迁移、来源与金句模型在 P2 完善；不将最小模型描述为最终数据模型。
- P1 没有实现敏感信息永久清除与 removed 终态；当前只验证下架。永久清除仍需按 P5 的正文、媒体、引用与备份策略实现。
- 依赖审计仍有 5 项包级中风险告警；没有执行外部渗透测试或容量压测，不承诺生产安全与最大承载能力。
