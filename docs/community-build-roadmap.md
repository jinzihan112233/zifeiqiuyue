## 1. 目标、现状与使用方式

### 1.1 最终目标

- 保留淡黄色木浆纸、简线、微古风的阅读体验。
- 使用用户名、密码、邀请码注册，无需手机号或邮箱。
- 编辑发布文章，成员提交社区帖子，管理员审核和管理内容。
- 支持文章及帖子的整篇评论、文章内选中文字批注，以及对所有评论继续回复。
- 普通帖子先审核再公开；评论先公开，再由管理员处理举报或违规内容。
- 网站可维护、可备份、可迁移，后续增加搜索、收藏、点赞、通知时不破坏已有内容关系。

### 1.2 起点与当前仓库事实

- 起点为 HTML、CSS、原生 JavaScript 静态站；当前同时包含 Next.js / Payload 社区应用、账号及 PostgreSQL 数据层。
- 离线文章来自 `content/articles/*.md`，金句来自 `content/quotes.json`，首页推荐来自 `content/site.json`；社区应用已独立读取数据库。
- `scripts/build-content.cjs` 将内容构建为 `assets/generated/content.js`，支持直接打开本地 HTML。
- 文章已有稳定 ID，例如 `libai`，旧入口形式为 `read.html?id=libai`。
- 旧演示 Markdown 尚未人工整理成四段；社区已实施“开头、简介、正文、后记”提交校验，导入不会自动补写。
- 离线内容与社区各有测试；P5 历史记录合计 88 项通过，仍不能替代人工专项、统一安全审查或生产验收。
- 示例内容保留 `demo` 与来源信息，不自动变为真实作者文案；网站继续保持非官方身份，除非获得相应授权。

### 1.3 如何执行

1. 按 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9 顺序推进；P6 与 P7 不必同时上线。
2. 每一步只完成指定交付，不提前引入下一阶段的复杂功能。
3. 每阶段通过验收后再扩大变更；失败时先修复，不把未验证条件带入正式环境。
4. 将首次实现限定为一个应用、一个数据库、一套文件存储；按真实负载再拆服务。
5. 每阶段用独立的小提交记录变更；部署和数据迁移单独记录，不自动发布到外部平台。

## 2. 统一规则与架构边界

### 2.1 技术方向

采用 TypeScript + Next.js + Payload + PostgreSQL，图片使用兼容 S3 的私有对象存储。开发环境允许使用有相同访问权限行为的本地受控存储。前台、后台和业务 API 位于同一应用、同一站点来源。

Payload 负责认证、后台、基础数据操作和编辑历史；社区代码负责邀请码、审核状态转换、发布快照、回复关系、批注定位和管理行为。保留现有视觉样式和 Markdown 内容，页面逐步迁移到新应用。

研究时 npm 的 Payload 稳定版为 3.91.0，4.0 为测试版；这只是调研记录。P1 开始时重新核验稳定版本、安全公告、Node.js 和 Next.js 兼容范围，锁定通过验证的版本与锁文件。不要把 `latest` 当作长期可复现的版本约定。

本次开发自行实现简单审核流程，不依赖可能另有付费条件的企业工作流产品。

### 2.2 默认产品规则

本表覆盖完整社区的目标规则，其中评论、回复、举报已在 P6 本机实现；扩展批注与公网能力仍按后续阶段推进。各项实现状态以对应阶段记录为准。

| 项目 | 第一版规则 |
| --- | --- |
| 游客 | 可读公开内容；不能发帖、评论或查看待审内容 |
| 成员 | 维护自己的草稿、提交帖子、评论、回复、举报 |
| 编辑 | 维护与发布授权范围内的站方文章、金句、推荐；不管理账号角色 |
| 管理员 | 管理邀请码、用户、帖子审核、举报、下架、封禁与操作记录 |
| 官方身份 | “站方发布”与“作者本人官方授权”分开；未获授权时不冒用官方身份 |
| 审核人 | 普通帖子由管理员审核；成员不能审核，编辑不默认获得该权限 |
| 文章格式 | 站方文章要求四段；社区帖子自由使用 Markdown，不强制四段 |
| 简介 | 站方文章简介生成列表摘要，不再单独维护一份相同描述 |
| 内容可见性 | 初期公开阅读、邀请参与；不做私密圈子或付费内容 |
| 评论 | 登录后即时公开，允许回复；所有写入均受内容及账号状态约束 |
| 新版稿件 | 已发布内容修改后重新提交，旧发布版继续展示 |
| 评论删除 | 正文擦除并保留占位和回复关系；管理隐藏为独立状态 |
| 账号恢复 | 使用一次性恢复码；不依赖短信、邮件或公开昵称确认身份 |

以上为本规划的实施默认值，若调整，应先更新本文件及相关验收条件。

### 2.3 数据主来源

- 当前静态站继续以仓库文件为主来源。
- 本机社区应用已以数据库为运行内容来源；P9 公网切换后仍保持数据库为唯一在线主来源，仓库 Markdown 用于模板、显式导入和导出。
- 不同时启用“仓库改动覆盖数据库”和“网页编辑覆盖仓库”的双向同步。
- 内容导出包含 Markdown、元数据和媒体映射；账号、评论及审核记录由数据库备份保存，不承诺用文章导出恢复整站。
- Git 仓库不存数据库转储、恢复码明文、邀请码明文清单、会话、用户上传或生产密钥。

### 2.4 数据关系

| 对象 | 最少职责与关键关联 |
| --- | --- |
| 用户 | 登录名、昵称、角色、状态；认证字段由框架安全存储 |
| 邀请码 | 哈希、有效期、上限、已用次数、撤销状态；使用记录关联用户 |
| 内容 | 稳定 ID/slug、文章或帖子类型、作者、当前发布快照、可见状态 |
| 工作稿 | 当前编辑内容与修订号；成员只能访问自己的工作稿 |
| 提交稿 | 某次提交的不可编辑副本、提交人、审核状态、审核意见 |
| 发布快照 | 审核通过的不可变正文、标题、来源、时间与渲染规则版本 |
| 评论 | 所属内容、父评论、根评论、作者、正文、编辑时间、管理状态 |
| 批注定位 | 关联顶层评论与发布快照，保存引用、上下文和文字位置 |
| 金句 | 正文、署名、出处、排序；可关联内容及其发布快照 |
| 媒体 | 所有者、存储键、文件类型、尺寸、所属稿件/发布快照引用 |
| 举报 | 目标、理由、处理状态、处理人；目标关系须保留 |
| 管理记录 | 操作人、动作、对象、时间、理由；不记录密码或令牌 |

评论与举报对象已在 P6 建立，并与原批注定位关联。发布快照在普通编辑发布流程中不可改写，敏感清除属于受控例外，会清除正文并保留终态和审计事实。

工作稿、提交稿、发布快照承担不同职责：可编辑 → 冻结送审 → 公开引用。实现时可以使用合理的 Payload 集合组合，但不得因合并存储而失去三者的隔离。Payload 编辑历史仅辅助编辑，不替代长期发布快照。

## 5. P2：建设内容基础与迁移工具

2026-10-21 已完成本机 P2 实现与验证，见 [P2 验证记录](history/phase-2-validation.md) 与 [内容维护指南](content-guide.md)。六篇旧演示文章作为未公开草稿迁入，尚未人工整理为完整四段。P3–P5 已继续实施，状态见后续章节。

### P2-01 实现稳定内容标识

- [x] 分配数据库内部 ID，并保留现有文章文件名为稳定 slug；标题修改不改变链接。
- [x] 将站方文章、社区帖子作为明确的内容类型；公开状态与稿件审核状态分开。
- [x] 为 slug、版本关联与外键建立约束；常用列表按内容类型、状态、发布时间建立索引。

交付：内容模型与查询。验收：同名 slug 不能重复，文章改名不影响旧链接。

### P2-02 统一 Markdown 与四段格式

- [x] 站方文章只允许一个开头、简介、正文、后记，按此顺序出现；正文内可使用更低级标题。
- [x] 简介用于摘要，保留一个来源；列表展示用从简介提取的纯文本，不另存人工重复字段。
- [x] 旧文章缺少四段时在迁移报告中列明，保留正文并人工整理；不得编造开头、简介或后记。
- [x] 渲染禁用原生 HTML，限制链接协议并清理输出；前台预览与正式阅读共用渲染器。
- [x] 正文图片只引用本站受控媒体；禁止远程图片、`data:` 图片及任意嵌入。普通来源超链接可保留，既有外链图片在迁移报告中列出，由编辑审核后人工导入，不由服务端自动抓取。

交付：格式约定、模板与渲染规则。验收：标题、列表、表格、代码、图片和恶意链接均有实际样例检查。

### P2-03 实现发布快照与长期引用

- [x] 发布快照包含完整展示内容、规范文本、渲染规则版本、媒体引用和来源信息。
- [x] 作者或编辑不能原地修改快照；新发布生成新快照，并原子更新当前指针。
- [x] 保留被评论批注、金句引用的快照；下架或敏感信息清除策略优先于历史可读性。

交付：发布快照读写与版本阅读入口。验收：无法通过通用更新或版本恢复接口改写已发布快照。

### P2-04 迁移金句和首页配置

- [x] 将现有金句导入独立记录，保留 ID、署名、来源、演示标识及展示顺序。
- [x] 首页推荐只允许关联当前可公开内容；内容下架时金句、推荐与摘要同步处理。
- [x] 导出的内容包包含 `articles/` 与 `quotes/` Markdown 文件夹、图片和关联清单，满足仓库式维护与归档需求。

交付：金句与推荐管理。验收：不存在引用待审内容或下架内容的公开入口。

### P2-05 实现可重复导入与导出

- [x] 导入支持只读预览，先显示新增、重复、格式错误与缺失图片，再执行。
- [x] 使用旧 ID 映射防止重复导入；若数据库内容已有在线修改，报告冲突，不静默覆盖。

- [ ] 待审图片使用认证媒体代理；长期公开图片不使用会在正文里过期的签名 URL，所有地址在读取时判断可见性。

交付：生产配置检查表。验收：原图、派生图、下载接口与对象存储权限一致，公开缓存不绕过下架。

### P8-03 备份与恢复演练

- [ ] 初期目标：数据库每日备份、媒体增量备份，保留 30 天；备份存放于与应用不同的故障域，限制访问并加密。
- [ ] 小范围试运行默认最大数据损失目标 24 小时、恢复目标 4 小时；通过演练验证，未达到不得当作已保证指标。
- [ ] 恢复到独立环境，检查账号、文章、金句、媒体、评论关系与批注版本。
- [ ] 说明下架或清除的数据可能仍在保留期备份中，恢复后先重放清除记录，再开放访问。

交付：备份任务与恢复操作手册。验收：不是仅看到备份文件，而是实际恢复后能读取和操作。

### P8-04 日志、告警与基本运维

- [ ] 记录脱敏请求错误、发布失败、迁移失败与异常登录；不记录密码、Cookie、恢复码或邀请码。
- [ ] 监测数据库连接、磁盘/存储用量、请求错误与备份状态，明确管理员如何收到故障信息。
- [ ] 审核记录由应用限制为追加，不向普通编辑开放删除；数据库高权限管理员的能力不宣称为不可篡改。

交付：运维说明及故障处理入口。验收：主动制造一个无害的备份/请求失败，验证能发现问题。

### P8-05 小范围邀请试运行

- [ ] 先邀请 10–30 位成员，分配真实的投稿、退回、回复、举报和恢复任务。
- [ ] 使用代表性样本初测：500 篇内容、10,000 条评论、20 个并发会话；记录运行环境、错误、延迟及慢查询。
- [ ] 初期参考目标：列表与阅读 API 的 p95 小于 1 秒，持续 10 分钟无 5xx；不将该样本宣称为最大承载能力。
- [ ] 优先修复权限、数据丢失、定位和可访问性问题，再处理视觉细节。

交付：试运行问题单和实测报告。验收：阻塞项关闭，恢复流程通过，管理员有能力处理日常内容。

## 12. P9：正式切换与后续扩展

### P9-01 切换线上内容来源

- [ ] 上线前冻结旧仓库的内容写入，执行最后一次导入，核对数量、链接和图片。
- [ ] 保留旧静态版本的可恢复归档；新社区切换后，数据库为唯一写入来源。
- [ ] 更新 README，明确新开发、发布、导出和维护方式；静态双击模式仅属于归档版。

交付：切换记录。验收：新投稿进入数据库，不因重新部署旧文件而被覆盖。

### P9-02 明确回退边界

- [ ] 回退应用前检查数据库结构兼容；不把旧数据库备份直接覆盖上线后新增的数据。
- [ ] 若社区写入出现严重问题，先关闭写入并保留当前库，必要时切换只读阅读。
- [ ] 修复后迁移或重放已确认的数据，记录丢失风险；恢复上线前再检查角色、下架与清除状态。

交付：发布与事故回退手册。验收：演练一次只读降级，不破坏已提交的帖子和评论。

### P9-03 按需求扩展

- [ ] 第一批候选：站内通知、搜索、收藏、点赞；实际需求确定后单独写小计划。
- [ ] 收藏和点赞使用用户与目标的唯一约束；通知在数据库写入成功后派发，不影响发布事务。
- [ ] 先优化分页、索引和慢查询；任务积压再加队列，查询需求超出数据库能力再加搜索服务。
- [ ] 多实例部署前统一会话、限流、缓存失效和媒体存储；确有独立负载再拆服务。

交付：基于使用数据的下一轮需求。验收：扩展不改变既有内容 ID、评论关系和批注版本语义。

## 13. 业务接口与权限实现约定

以下是业务动作边界，具体 HTTP 路径在实现阶段统一登记；不是要求另造一套与 Payload 重复的 CRUD 框架。

| 动作 | 输入要点 | 必须由服务端保证 |
| --- | --- | --- |
| 注册 | 登录名、密码、邀请码 | 白名单字段、名额原子消耗、成员角色 |
| 保存稿件 | 内容 ID、预期修订号、正文 | 所有者、状态、长度、并发冲突 |
| 提交/撤回 | 工作稿修订号或提交稿 ID | 冻结副本、合法状态转换、防重复 |
| 审核 | 提交稿 ID、预期状态、决定、意见 | 审核权限、版本一致、原子发布 |
| 评论/回复 | 内容 ID、父评论、正文 | 内容可见、可讨论、同内容父子关系 |
| 批注 | 发布快照、文字范围、引用、评论 | 快照权限、规范文本验证、原子创建 |
| 管理 | 目标、预期状态、动作、理由 | 最新管理员身份、审计、关联可见性 |
| 媒体读取 | 媒体 ID | 原图及派生图均检查实际引用和可见性 |

- 用户普通操作沿用框架集合、字段权限；必要业务动作调用明确的服务端函数。
- 内部 Local API 明确指定用户和 `overrideAccess: false`，不依赖版本默认值；确需绕过的初始化或事务内部操作先完成显式授权，并限制可写字段。
- 默认关闭不需要的 GraphQL；启用时执行与 REST 相同的权限用例。
- 不只检查页面访问。REST、批量操作、版本读取/恢复、文件读取、后台动作和自定义接口都要检查。
- 私密请求不进入公共缓存；分页、关系展开、计数、错误和用户资料都遵守可见性。
- 用户可改字段由服务端白名单控制。框架字段权限可能静默丢弃字段，不等于完成了状态转换校验。

## 14. 必须验证的漏洞与冲突清单

| 编号 | 风险/冲突 | 修正与证明方式 | 所属阶段 |
| --- | --- | --- | --- |
| R01 | 绕过邀请码直接创建用户 | 测试底层创建及其他 API 路径均不能绕过 | P1、P4 |
| R02 | 单次邀请码并发重复使用 | 条件更新或锁 + 事务；10 并发只成功一次 | P4 |
| R03 | 注册或资料修改提权 | 传入角色、状态、作者等字段，验证无效且权限不变 | P4、P5 |
| R04 | 内部 API/版本接口绕过权限 | 直接测试 Local API、REST、版本及关系展开 | P1、P5 |
| R05 | 审核期间正文被偷换 | 修改工作稿后批准旧提交，只能发布被审副本 | P5 |
| R06 | 双人审核或撤回竞争 | 条件转换，只能一个终态，无重复快照 | P1、P5 |
| R07 | 草稿、恢复信息或其他用户数据进入缓存 | 两账号加游客交替读取，响应互不泄露 | P3–P5 |
| R08 | 待审图片或缩略图提前公开 | 无 Cookie 访问所有媒体地址均失败 | P1、P8 |
| R09 | 下架后旧版本/批注引用仍暴露 | 按正文、历史、媒体、金句、引用、缓存逐项检查 | P5、P7 |
| R10 | 批注偏移按不同字符单位计算 | 中文、emoji、组合字符和跨标签往返测试 | P7 |
| R11 | 删除父评论导致回复丢失 | 删除占位保留关系，不级联删除他人内容 | P6 |
| R12 | 评论编辑解除管理员隐藏 | 修改被隐藏正文后仍不能公开 | P6 |
| R13 | 回复跨文章、循环或引用不可见父级 | 伪造关系应失败，创建后关系不可编辑 | P6 |
| R14 | Cookie 误用或脚本注入 | 跨站写入、恶意 Markdown、危险协议测试 | P1、P2、P8 |
| R15 | 上传伪装文件、超大图片或外链抓取 | 真解码、大小/像素限制、禁 SVG、禁任意服务端抓取 | P8 |
| R16 | 仓库与数据库互相覆盖 | 切换后仅数据库写入；导入冲突需报告 | P2、P9 |
| R17 | 备份无法恢复或恢复出已清除内容 | 独立恢复演练，开放前重放清除记录 | P8、P9 |
| R18 | 官方身份和非官方站点定位冲突 | 站方发布标识与作者授权标识分开 | P0、P3 |
| R19 | 通过发帖引用他人私有图片使其公开 | 保存、提交、发布均校验媒体绑定权限 | P1、P5 |
| R20 | 审核后替换图片或远程图片变化 | 文件不可覆盖、替换重审、拒绝外链图片 | P2、P5、P8 |

这些是设计风险与验收用例，尚未进行渗透测试，不能标记为“已修复”。
