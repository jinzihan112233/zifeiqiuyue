# P5 详细构建计划：投稿、审核与内容管理

状态：使用者已确认并授权实施。功能实现与本机自动验证见 [P5 实现、教程与验证记录](phase-5-validation.md)；人工专项待验收。下文保留原构建计划，不将其验收方法全部视为已执行。

## 1. 阶段定位与目标

总流程从 P0 起算，所以“第六个阶段”对应 **P5**，其后才是 P6 评论、回复、举报与管理。

目标：让受邀成员可以可靠地写帖、配图、保存、提交和撤回；让管理员能够看清具体提交版本、填写审核意见、发布、下架和恢复；让读者能从正式入口阅读已发布帖子。站方四段文章沿用相同的版本和审核机制。

继续使用现有 Next.js、Payload、PostgreSQL、Markdown 和淡黄纸本界面，基于现有业务服务补齐交互与校验。默认不新增编辑器框架、差异库、消息队列或其他基础依赖。

P3 状态保持“使用者初步验收通过，待后续统一漏洞审查”。P4 已完成本机实现及自动验证，但尚未收到使用者明确的最终验收；本计划不替使用者勾选验收，也不把既往测试结果等同于安全审计。

## 2. 已有能力和本阶段缺口

以下是对当前源码的定向检查，不是全仓库漏洞审计：

| 已有实现 | 本阶段补齐或修正 |
| --- | --- |
| Markdown 输入、预览、修订号保存 | 未保存提示、冲突保留本地稿、明确保存状态、图片插入操作 |
| 冻结提交、一个内容至多一份待审稿 | 网络重试可识别同一提交；明确区分编辑稿、待审稿和公开稿 |
| 管理员审核、编辑发布自己的站方文章 | 分页队列、冻结正文及图片预览、版本差异、自由填写理由、审核历史 |
| 在事务内创建快照、更新当前指针 | 审核目标及预期状态校验、动作审计、并发与故障回归 |
| 下架/恢复及公开媒体权限 | 填写理由、操作记录、全部关联入口验证、敏感清除流程 |
| 账号中心和现有文字批注 | 链接到指定稿件、正式帖子列表和帖子阅读入口 |

已发现的具体问题需优先处理：

1. 工作台接口对多个集合固定 `limit: 100`，没有服务端分页；记录较多时无法在页面继续查看。
2. 当前退回按钮使用固定的“请修改后重新提交”，无法表达实际修改意见。
3. 审核服务在区分批准、退回、撤回之前校验媒体；图片不可用可能阻止退回或撤回。
4. 审核理由使用 `slice(0, 1000)`，会静默截断；应改为明确的长度校验和表单提示。
5. 管理员在现有媒体校验中可以跳过归属限制；“管理权限”和“绑定他人媒体的授权”需要分开。

## 3. 业务规则先固定

### 3.1 三份内容各负其责

```text
工作稿 revision N ──提交──> 冻结提交稿 pending ──通过──> 发布快照
        │                          ├─退回──> 返回修改意见
        └─继续修改为 N+1           └─撤回──> 结束该次提交

继续保存工作稿，不修改待审副本或已发布快照。
已下架内容通过新版本审核后仍保持下架，由管理员单独恢复。
```

稿件状态和公开状态分开维护：提交稿使用 pending/approved/returned/withdrawn；内容使用 unpublished/public/hidden。敏感清除增加终止状态 purged，不能恢复、再提交或再次发布。

建议已发布内容删除/下架先走可恢复的“下架”。普通成员不能直接改变公开指针和公开状态；暂不新增作者自行撤稿下架的权限。

### 3.2 权限矩阵

| 操作 | 普通成员 | 编辑 | 管理员 |
| --- | --- | --- | --- |
| 创建、编辑帖子 | 自己的帖子 | 自己的帖子 | 可管理全部，记录代改行为 |
| 创建站方四段文章 | 不允许 | 自己创建和维护 | 可管理全部 |
| 提交、撤回 | 自己的待审投稿 | 自己的待审投稿 | 可代操作并记录原因 |
| 审核成员帖子 | 不允许 | 不允许 | 允许，包含自审标识 |
| 发布站方文章 | 不允许 | 自己的站方文章 | 允许 |
| 下架、恢复、敏感清除 | 不允许 | 不允许 | 允许，要求理由 |
| 查看他人草稿及审核内部信息 | 不允许 | 不允许 | 仅管理用途 |

每次写操作由服务端重新检查有效账号和目标权限。作者被封禁后，其待审稿保留但暂停批准；解禁后可重新处理。封禁不自动下架其全部已发布内容，下架作为单独、留痕的管理动作。

### 3.3 媒体绑定规则

- 默认只允许作者为新正文绑定自己的媒体；管理员身份不自动授予绑定别人图片的权利。
- 审核批准校验的是投稿作者已有的媒体绑定依据，不应要求审核人拥有投稿图片。
- 管理员代改他人工作稿可保留该内容已获准绑定的媒体；新增图片需满足明确归属或授权。P5 不新增通用媒体共享系统，不满足条件时拒绝新增绑定。
- 对已有跨作者引用先生成受限审计清单，不自动改归属或拆除已发布历史版本；不明确的绑定在再次送审前解决。
- 上传和替换均创建新记录、新随机存储键，校验实际字节哈希；原图、缩略图和替代文字不原地覆盖。
- 图片替代文字随提交冻结；不能依靠修改媒体说明偷偷改变已审核展示。

## 4. 逐步实施

### P5-00：记录基线与专项核查

**步骤目标**：确定哪些能力可以复用、哪些必须修正，保留可恢复基线。

**构建方法**：

1. 记录 Git 状态，保留既有源码、用户文章及所有未提交修改。
2. 备份开发库、测试库、媒体及静态源文件哈希；不打印账号凭据。
3. 核查现有提交、媒体和公开快照引用，报告跨作者媒体、缺失文件、异常状态和重复待审记录。
4. 定向检查注册/封禁后投稿权限、通用 API 绕过、Markdown 渲染和媒体访问；发现会破坏本阶段流程的问题先修复。
5. 建立 P5 验收表，并区分“已检查”“待执行”“用户初步验收”。

**验证方法**：原有 70 项自动测试作为回归基线；开发与测试库可备份；审计只读运行两次结果稳定；原静态页面和文章哈希不变。

### P5-01：补齐状态、审计和迁移约束

**步骤目标**：管理动作有明确状态和可追溯记录，避免将所有需求塞进前端。

**构建方法**：

1. 保留 contents/drafts/submissions/snapshots 模型，只增加实际需要的字段与约束。
2. 增加受控的内容动作记录：操作者、动作、内容稳定 ID、提交/快照标识、时间、理由、自审或代操作标记。普通成员只看自己的审核反馈，内部记录仅管理员可读。
3. 发布、退回、撤回、下架、恢复、敏感清除写动作记录；记录与业务变更同事务，不记录密码、恢复码或被清除的原文。
4. 使用唯一约束保证一内容至多一份待审副本、一份提交至多一个发布快照；添加分页和管理队列需要的索引。
5. 对 purged 内容在全部受控写入及公开读取入口统一拒绝；未来评论模块也必须遵循父内容状态。
6. 迁移采用显式脚本，先测试库再开发库；已有冲突先报告，不能自动删除重复记录。

**验证方法**：伪造状态、作者、公开指针和审计字段均被拒绝；触发异常时正文、状态、指针、审计同时回滚；旧记录不被重新发布；迁移前后的内容数与引用符合预期。

### P5-02：编辑页与防丢稿体验

**步骤目标**：明确“正在编辑什么、哪些已保存”，不会因切换页面或冲突静默丢稿。

**构建方法**：

1. 将工作台拆成列表及按内容 ID 打开的编辑页，沿用已有保存服务与 CSS；从个人中心可直接进入对应稿件。
2. 显示最近保存时间、当前修订号、未保存标记和当前公开状态。
3. 保存携带修订号；只有服务端明确成功才更新“已保存”状态。
4. 冲突返回 409，保留本地编辑文本，提供复制/下载本地稿及重新读取服务端版本的选择，不自动覆盖。
5. 有未保存内容时，站内切换主动提醒；刷新/关闭使用浏览器支持的离开提示，同时保留手动导出方式。提示不能当作崩溃恢复保证。
6. 暂不把私人工作稿持续保存到 localStorage，不做自动保存和多人协作。
7. 站方文章展示开头、简介、正文、后记要求；普通帖子不强制四段。

**验证方法**：正常保存后刷新可读回；服务端失败、断网、会话过期均不显示保存成功；双标签页旧修订保存失败且文本保留；切换稿件不误把 A 的编辑内容写入 B；在浏览器实际验证离开提示和下载。

### P5-03：图片插入、不可变媒体与一致预览

**步骤目标**：上传后可以便捷插图，预览与最终发布的图片、正文一致。

**构建方法**：

1. 在编辑器旁显示可绑定的图片，提供“插入光标处”，生成已有 `media:ID` Markdown 语法。
2. 复用实际图片解码、尺寸、文件大小及转 WebP 校验；文件扩展名不作为安全依据。
3. 图片替换新建媒体；补查完整图、缩略图与哈希，不允许通用 API 改写已有文件和说明。
4. 保存、提交、批准使用统一的归属/授权校验；渲染读取冻结媒体信息。退回和撤回不被失效图片阻塞。
5. 预览复用服务端 Markdown 渲染和 URL 校验，不采用第二套客户端渲染规则。

**验证方法**：插入位置和图片替代文字正确；伪图片、SVG、超限图片和越权绑定失败；上传完成不自动公开；待审后替换工作稿图片不影响审核副本；保存预览与公开版本的 HTML、图片引用和哈希一致。

### P5-04：冻结提交、撤回及网络重试

**步骤目标**：每次提交对应明确的修订，重复点击不生成重复任务。

**构建方法**：

1. 未保存时显示“先保存再提交”，由用户明确选择；服务端只接收已保存修订。
2. 冻结标题、正文、元数据、来源信息、媒体引用和替代文字。
3. 为提交使用稳定请求标识：同一用户、内容、修订、相同请求的重试返回原结果；改动请求内容不允许复用同一标识。
4. 同一内容已有其他待审稿时返回冲突；重复提交旧修订不能绕过约束。
5. 撤回携带具体提交 ID 与预期 pending 状态；已批准/退回/撤回的稿件不能改回 pending，修改后创建新提交。

**验证方法**：冻结 A 后将工作稿改成 B，审核仍读 A；双击及响应丢失重试只产生一个提交；不同标签页旧修订提交失败；撤回与批准竞争只有一个成功；失效图片仍能撤回。

### P5-05：审核队列、全文预览与版本差异

**步骤目标**：审核人看到的就是将发布的那个版本。

**构建方法**：

1. 提供分页、状态及内容类型筛选；在数据库筛选后分页，时间相同以 ID 排序。
2. 审核详情展示冻结正文、配图、来源、演示标识、作者公开昵称、提交时间和修订号，不读取最新草稿代替提交稿。
3. 并排展示当前发布版与待审版；逐项标识标题、元数据和媒体变化。若补充文本差异，仅对转义后的文本做有上限的行比较；长稿保留并排原文，不运行无界全文 diff，也不执行未清洗 HTML。
4. 展示该内容历史提交及审核理由，管理员内部说明与作者可见理由分开。
5. 退回必须填写 1–1000 字符理由，超限明确拒绝；通过、撤回可填写备注。管理员自审显示清楚的“管理员自行发布”记录。

**验证方法**：编辑无法查看或批准成员投稿；成员不能读取他人待审标题、正文和理由；长正文、缺图、空队列及末页正常；历史版本和新工作稿不混淆；输入脚本不会在差异界面执行。

### P5-06：审核动作、原子发布与并发边界

**步骤目标**：不会重复发布、错发版本或因回滚产生半完成状态。

**构建方法**：

1. 审核请求指定提交 ID、决定和预期 pending 状态；服务端按内容锁重新读取冻结提交、当前权限及作者有效状态。
2. 保留“更新审核状态 → 创建不可变快照 → 更新当前指针 → 写动作记录”的单事务流程。
3. 批准时重新校验冻结媒体与四段文章结构；退回、撤回只校验操作所需的身份与状态。
4. 请求重试可以查询已经完成的同一决定，不能生成第二个快照；与不同决定冲突时返回 409。
5. 下架内容批准新稿后仍下架；恢复必须另行执行。
6. 明确封禁与写入的并发顺序：账号更新与受保护写入应有一致的数据库锁顺序，使先取得有效写权限并提交的操作可完成，封禁提交之后开始取得权限的操作失败。禁止用事务内旧角色缓存替代当前状态检查。

**验证方法**：批准/批准、批准/退回、批准/撤回并发只有一个决定成立；快照创建后注入失败可完全回滚；大于连接池规模的任务不会等待自身占用的连接；封禁与审核并发符合已定义顺序；撤销旧会话后不能新增内容或上传。

### P5-07：公开帖子入口与发布后的编辑

**步骤目标**：成员发布后有正式、可发现的阅读入口。

**构建方法**：

1. 增加 `/community` 分页帖子列表及 `/posts/<slug>` 阅读页；复用现有 Reader、公开投影和纸本样式。
2. 站方文章保留 `/articles`；帖子按本站发布时间倒序，同时间以稳定 ID 排序，不套用原视频日期。
3. 公开查询仅返回 public 帖子的发布快照，保留版本参数和文字批注；旧 `/lab/read/<id>` 继续兼容。
4. 本阶段公开读取继续使用不缓存或及时回源策略，带身份响应一律 no-store，不新增缓存基础设施。
5. 已发布内容再次编辑和提交不影响当前读者所见版本；个人中心链接指向新正式入口。

**验证方法**：游客只能看到公开快照；文章/帖子路由不能跨类型读取；草稿更新、未审稿和审核理由不出现在 SSR HTML 或接口中；分页稳定；更新发布后列表、正文和版本指针对齐；历史批注仍定位原快照。

### P5-08：下架与恢复

**步骤目标**：普通管理动作可恢复，且不会留下公开旁路。

**构建方法**：

1. 管理员填写下架/恢复理由并确认具体内容和当前状态，写入动作记录。
2. 下架遮蔽正文、历史公开版本、结构化关联金句、推荐、现有批注及新增批注入口。
3. 媒体公开性按全部公开引用计算；没有其他公开引用的原图和缩略图停止对游客提供，拥有者/管理员仍可用于管理。
4. 被其他公开文章合法共享的媒体不能因一篇下架而被删除；页面明确报告这一情况，不声称文件全站消失。
5. 恢复只针对曾发布、未清除的内容；不会自动批准待审工作稿或恢复已单独禁用的金句。

**验证方法**：下架后访问目录、阅读、旧链接、历史参数、金句、推荐、批注及独占媒体均不可公开读取；共享媒体的其他内容仍正常；恢复后仅恢复合规引用；发布新版本不能偷偷解除下架。

### P5-09：敏感清除及延迟媒体清理

**步骤目标**：区分“隐藏”和“从当前运行数据中清除”，明确不可恢复操作的影响。

**构建方法**：

1. 提供管理员清除预检，只返回范围和数量：工作稿、Payload 草稿历史版本、提交稿、全部快照、标题/摘要/来源等敏感字段、结构化关联金句、批注正文及摘录/前后文、媒体及其他引用。不能只清空当前 Markdown。
2. 无结构化关联的手工摘抄不能可靠自动发现，预检明确列为人工核查，不进行无差别字符串替换。
3. 若敏感图片被范围外的公开内容引用，阻止“完整清除完成”，要求管理员明确扩展处理范围或先解决引用；不擅自删除别人的文章。
4. 用户确认具体范围及不可恢复后，在事务内遮蔽/清除运行库正文、写入 purged 终止状态和不含敏感原文的审计记录。预检还须检查可能复制原文的审核理由和管理备注，必要时清除敏感文字并保留动作事实。保留必要的稳定标识和外键占位，不伪造空白发布版。普通工作流不得修改快照；敏感清除是单独受控、审计留痕的例外，清除后的占位不再作为可渲染/可导出的完整快照。
5. 文件删除在数据库提交后执行；将待清理任务持久保存，可失败重试且幂等。逐项重查所有引用，只处理约定存储目录内经过路径校验的文件及派生图，不接受客户端路径。
6. 数据库或文件失败时显示“处理中/待重试”，只有数据库清除、引用检查和目标文件清理均满足条件才显示完成；不引入 Redis。
7. 已导出的私有包、旧备份和读者已下载内容不在运行库事务内。清除清单需独立保留；恢复旧备份只能先在隔离环境执行，并按最新清除清单重放后再开放读取。清单缺失时不得自动恢复公开服务。

**验证方法**：用唯一测试标记建立含历史稿、发布版、批注、金句和图片的内容，清除后检查所有运行库副本与接口；旧版本、个人中心和导出均不能再返回该标记；共享媒体冲突能被阻止；文件删除失败可恢复执行；重复清理不会删除新文件或他人媒体；恢复演练验证清除清单不会被旧备份覆盖。

实际实施时只使用合成测试内容演练，不自动清除用户现有文章。此处的确认是不可恢复清除功能本身的必要交互，不是普通保存或审核的额外审批。

### P5-10：界面整合与人工验收

**步骤目标**：成员写作和管理员管理都有连续、可理解的操作路径。

**构建方法**：

1. 工作台保留简洁入口，按角色展示“我的内容、编辑页、我的提交、审核队列、内容管理”，避免单页堆叠全部稿件。
2. 复用纸黄、墨灰、细线、宋体标题，不引入新视觉体系。
3. 为表单设置标签、长度提示、加载状态、错误定位和提交完成提示；禁止仅用颜色表示状态。
4. 手机单列、桌面编辑/预览并排；长标题、Markdown 表格和代码块局部滚动，不撑破整页。

**验证方法**：在 Edge 实测 375/768/1280px、200% 缩放和纯键盘流程；验证移动设备的输入、长按选字和触摸操作。不能使用 HTTP 测试替代；无法执行的项目记录为待验收。

### P5-11：回归、恢复演练与交付

**步骤目标**：得到可以验收的完整 P5，而非仅演示按钮。

**构建方法**：

1. 新增投稿管理集成/HTTP 测试，覆盖前述状态、权限、并发、重试、媒体及清除场景。
2. 跑现有账号、社区、内容、阅读与离线站测试，生产构建和类型检查；不预先承诺新增测试数。
3. 恢复隔离库并验证登录、投稿、待审状态、发布版本、媒体、动作记录及清除任务；检查最新清除清单的重放流程。
4. 交付 P5 验证记录、成员/管理员教程、接口及数据变更说明，更新总流程。
5. 保留用户未提交修改；不自动提交、推送、对外部署或改变真实文章公开状态。

**验证方法**：自动检查必须真实通过；人工记录分开列明；旧静态内容哈希保持不变；初始化账号和旧文章仍可用；备份恢复后不出现已清除内容重新公开。

| 潜在冲突 | 处理方式 |
| --- | --- |
| 第六阶段被误认为 P6 | 本阶段明确为 P5，评论系统仍在下一阶段 |

| 下架独占图与共享图混淆 | 独占媒体停公开；共享媒体按其他引用判断 |

| P5 顺便扩大到完整社区 | 仅补帖子公开入口；评论、回复、举报继续 P6，文本锚定扩展继续 P7 |

## 7. 阶段出口

使用者最终应能走通：

1. 成员登录 → 写帖 → 插图 → 保存 → 预览 → 提交 → 查看审核反馈。
2. 管理员打开具体冻结稿 → 对照已发布版 → 填理由通过或退回 → 查看操作记录。
3. 游客在帖子列表读到新快照；作者编辑下一稿期间，游客仍读到上次发布版。
4. 管理员下架后公开入口同步停止提供内容，恢复不误发草稿；敏感清除经预检和明确确认后，运行库和目标媒体完成清理且不可恢复。

本文件保留计划编写时的实施方案；现已按使用者授权完成构建，实际通过与待验收项见 P5 验证记录。浏览器/真机和跨阶段安全审查单独记录，原有 70 项通过仅作为历史基线。
